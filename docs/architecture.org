* Gowl Architecture
:PROPERTIES:
:CUSTOM_ID: gowl-architecture
:END:
** Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:
Gowl is a GObject-based Wayland compositor built on wlroots (0.19 or 0.20; see [[#wlroots-version-abstraction]]). Inspired by dwl and dwm, it reimagines their tiling window management philosophy with a full GObject type system, providing a modular, introspectable compositor with a plugin architecture based on GModule and GObject interfaces.

The design philosophy is to expose every compositor subsystem as a well-typed GObject, making it possible for modules to hook into any part of the compositor lifecycle through a set of clearly defined interfaces.

** Module / Plugin System
:PROPERTIES:
:CUSTOM_ID: module--plugin-system
:END:
*** How Modules Work
:PROPERTIES:
:CUSTOM_ID: how-modules-work
:END:
Modules are shared objects (=.so= files) that export a single entry point:

#+begin_src C
G_MODULE_EXPORT GType
gowl_module_register(void)
{
    return MY_TYPE_MODULE;
}
#+end_src

The =GowlModuleManager= loads the =.so= via =g_module_open()=, calls =gowl_module_register()= to get the =GType=, instantiates the module, and classifies it into dispatch arrays based on which interfaces the module implements.

*** Module Lifecycle
:PROPERTIES:
:CUSTOM_ID: module-lifecycle
:END:
1. *Load* -- =g_module_open()= on the =.so= file.
2. *Register* -- =gowl_module_register()= returns the module's GType.
3. *Instantiate* -- =g_object_new()= creates the module instance.
4. *Classify* -- The module manager checks which interfaces the instance implements and adds it to the corresponding dispatch arrays.
5. *Activate* -- =gowl_module_activate()= calls the virtual =activate= method.
6. *Dispatch* -- Events are dispatched to interface-specific arrays in priority order.
7. *Shut down* -- =gowl_module_manager_dispatch_shutdown()= calls every =GowlShutdownHandler= while the compositor is still alive.
8. *Deactivate* -- =gowl_module_deactivate()= when a module is disabled, and from the module manager's dispose for every module still active.

The compositor only borrows the module manager, so at exit the manager goes last: =main()= dispatches shutdown, finalizes the compositor, then releases the manager. Step 8 therefore runs with the compositor already gone, and a module must not touch it there: it holds the compositor with a weak pointer, or connects with =g_signal_connect_object()=, and does not count on step 7, which an embedder may skip (cmacs's =gowl-stop= does). See /A module outlives the compositor/ in =docs/modules.org=; =tests/test-compositor-teardown.c= holds it.

*** Module Priority
:PROPERTIES:
:CUSTOM_ID: module-priority
:END:
Each module has a =priority= property (integer). Dispatch arrays are sorted in ascending priority order (lower value = dispatched first). This allows modules to control ordering, for example a keybind handler module with priority 0 runs before one with priority 100.

*** Module Signals
:PROPERTIES:
:CUSTOM_ID: module-signals
:END:
=GowlModuleManager= emits:

- =module-loaded= -- after successful registration
- =module-activated= -- after successful activation
- =module-deactivated= -- after deactivation
- =module-error= -- on any module operation failure

*** Module Search Paths
:PROPERTIES:
:CUSTOM_ID: module-search-paths
:END:
Each module enabled in the YAML config is looked up as =<name>.so= in, in order:

1. =<exe-dir>/modules/= -- next to the running binary; =build/release/modules/= in a development tree
2. =GOWL_MODULEDIR= -- the compile-time =$(LIBDIR)/gowl/modules= (=/usr/local/lib/gowl/modules/= with the default prefix)

The first directory that has a given name wins, so a development build
shadows an installed copy.  =gowl_module_search_dirs()= in =src/main.c=
is the single definition of that order, used both by the loader and by
=--list-modules=; =--list-modules-ex= prints the file each module would
be loaded from and names the copies it shadows, which is not visible any
other way and is exactly what makes a fix appear not to have taken.

*The listing is produced by looking, not from a list.*  It used to be a
table in =src/main.c=, and it drifted: by the time anybody checked it was
missing six of the twelve layout modules and a third of everything else,
which made it look as though those layouts were not modules at all.
Nothing failed --- a stale list still prints --- so
=tests/test-list-modules.sh= compares the output against the module
directory.

The first directory that has the file wins. There is no home-directory search; =gowl --help= prints the resolved list.

*** Dispatch Semantics
:PROPERTIES:
:CUSTOM_ID: dispatch-semantics
:END:
There are two dispatch patterns:

1. *Consumable* -- The event is dispatched to handlers in priority order. The first handler that returns =TRUE= (or a non-NULL result) consumes the event and no further handlers are called. Used by: =GowlKeybindHandler=, =GowlMouseHandler=, =GowlClientPlacer=, =GowlIpcHandler=, etc.

2. *Broadcast* -- Every handler is called regardless of return value. Used by: =GowlStartupHandler=, =GowlShutdownHandler=, =GowlClientDecorator=.

** Configuration System

:CUSTOM_ID: configuration-system

*** Dual Config Architecture
:PROPERTIES:
:CUSTOM_ID: dual-config-architecture
:END:
Gowl supports two configuration mechanisms that work together:

1. *YAML Config* (=config.yaml=) -- Declarative configuration for all standard settings, keybinds, rules, and module options. Parsed at startup.

2. *C Config* (=config.c=) -- Compiled to a =.so= and loaded via =g_module_open()=. The exported =gowl_config_init()= function runs after YAML loading, allowing it to override or supplement YAML values programmatically.

*** Config Precedence
:PROPERTIES:
:CUSTOM_ID: config-precedence
:END:
From lowest to highest priority:

1. Built-in defaults (hardcoded in =GowlConfig= property defaults)
2. YAML configuration file
3. C configuration module (=gowl_config_init()=)
4. CLI arguments

*** YAML Search Paths
:PROPERTIES:
:CUSTOM_ID: yaml-search-paths
:END:
The config loader searches for =config.yaml= in this order (first match wins):

1. =./data/config.yaml= (project directory, for development)
2. =~/.config/gowl/config.yaml= (user config, recommended)
3. =/etc/gowl/config.yaml= (system-wide config)
4. =/usr/local/gowl/config.yaml= (installation default)

*** C Config Search Paths
:PROPERTIES:
:CUSTOM_ID: c-config-search-paths
:END:
The config compiler searches for =config.c= in:

1. =~/.config/gowl/config.c= (user config)
2. =/etc/gowl/config.c= (system-wide config)

The compiled =.so= is cached in =$XDG_CACHE_HOME/gowl/config.so=. It is recompiled only if the source is newer than the cached =.so=.

*** Config Properties
:PROPERTIES:
:CUSTOM_ID: config-properties
:END:
All configuration values are exposed as GObject properties on =GowlConfig=, making them accessible via =g_object_get()= / =g_object_set()= and through GObject introspection bindings. The =changed= signal is emitted whenever a property changes, and =reloaded= after a full reload.

** XWayland (X11 Client Support)
:PROPERTIES:
:CUSTOM_ID: xwayland
:END:
When built with =BUILD_XWAYLAND=1= (the default) and the =Xwayland=
server binary is installed, gowl runs its own rootless XWayland so
unmodified X11 applications run inside the session.

- On startup (=gowl_compositor_start=) gowl creates a *lazy*
  =wlr_xwayland= (the X server process only spawns when the first X11
  client connects), binds the seat to it, and exports =DISPLAY= to its
  X display name (e.g. =:1=).  =DISPLAY= is re-asserted after the nested
  libdecor/GTK setup, which can perturb the environment, so children
  reliably inherit gowl's own X server rather than a parent session's.
- X11 windows are represented by the same =GowlClient= type as XDG
  toplevels.  A client is an X11 surface when =xwayland_surface= is
  non-=NULL=; the =client_is_x11()= / =client_surface()= accessors and
  small branches in the shared map / commit / resize / fullscreen /
  focus / destroy paths handle the two surface types uniformly (the
  dwl model).  Managed toplevels are tiled like XDG windows;
  override-redirect surfaces (menus, tooltips) float.
- =gowl_compositor_get_xwayland_display()= returns the X display name so
  integrators (e.g. cmacs's =gowl-spawn=) can point spawned X11 clients
  at it.

Build without it via =make BUILD_XWAYLAND=0= (drops the =xcb= /
=xcb-icccm= dependencies); the X11 code is then compiled out behind
=GOWL_HAVE_XWAYLAND= and the compositor is Wayland-only.

** Systemd user-session bootstrap

=gowl_compositor_start= also bootstraps the systemd user session
(=src/util/gowl-systemd.c=), which =gnome-session= does for GNOME but a
bare compositor launch does not.  It runs
=systemctl --user import-environment= for the live compositor env and
starts the shipped =gowl-session.target= (=Wants==graphical-session.target=,
which itself refuses manual start).  This brings up the
graphical-session-bound user services -- =xdg-desktop-portal=,
=flatpak-session-helper=, =gvfs= -- that flatpak and other graphical apps
depend on (without it, flatpaks get no Settings portal and mis-theme).
=gowl_compositor_quit= stops the target.  Best-effort: no-op where
=systemctl= is absent, and =GOWL_DISABLE_SYSTEMD=1= opts out.

Only in a seat session.  Nested or headless, gowl shares the user's
systemd manager with the desktop hosting it and leaves the session
entirely alone -- see [[file:building.org][building.org]].

In a real seat session (not nested =just gowl=) it additionally
=try-restart='s =xdg-desktop-portal= after importing the environment.  A
portal frontend left running by a *previous* login keeps that login's
=XDG_CURRENT_DESKTOP= -- read once at startup to choose portal backends
-- so screen-sharing's =ScreenCast= request keeps routing to a backend
that doesn't work under gowl (the GNOME backend needs Mutter) and
silently fails.  Restarting the frontend makes it re-read the live
=XDG_CURRENT_DESKTOP= (which must list a wlroots-class name, e.g.
=...:wlroots=, to match =xdg-desktop-portal-wlr='s =UseIn=).  The
seat-only guard is =nested_wl_backend == NULL=; a nested gowl never
touches the host session's portal.

** Locking, and the seat side of it
:PROPERTIES:
:CUSTOM_ID: locking-and-the-seat-side-of-it
:END:

The screen lock is a separate program, =gowl-lock= (=tools/gowl-lock/=),
not a module inside the compositor. It links no libgowl: it is a Wayland
client that holds the session through =ext-session-lock-v1=, draws the
prompt with cairo, and runs PAM in its own address space.

The split is about who owns the locked state. A lock built into the
compositor is only as safe as the process it runs in --- and under
=cmacs --gowl= that process is the editor, with an Elisp evaluator, an
MCP server and a D-Bus interface in the same memory as the password and
whatever PAM modules the system's stack dlopens. With the protocol, the
*compositor* owns the state: when the lock client goes away without
unlocking, =on_session_lock_destroy= keeps =locked= set and the session
stays sealed behind =locked_bg=. Then =lock_spawn_command= puts a new
lock screen up, bounded by =lock_respawn_allowed= so a lock binary that
dies on startup stops rather than spins.

Three things this needs from the compositor, each of which was missing:

- *=locked_bg= has to cover something.* It is created 0x0 and was never
  resized, so the opaque sheet that hides the desktop hid nothing. It
  covers the whole output layout now (=backdrops_sync=), which is what
  the two gaps the protocol exists for depend on: before the client's
  first frame, and after a client dies with no surface left.
- *Keys have to reach the lock client.* The locked branch of
  =compositor_handle_key= handed every key to the built-in lock module
  and returned, because that module was the only lock there had ever
  been. An external lock screen therefore received nothing at all. With
  =cur_lock= set the key now goes to the seat, where the lock surface has
  focus. Guarded by =tests/test-lock-input.c=, which is a real
  =ext-session-lock-v1= client in a headless compositor.
- *Lock surfaces have to follow their outputs.* Unplugging a display
  mid-lock moves the ones beside it;
  =gowl_compositor_arrange_lock_surfaces= re-places and re-configures
  each from the layout change, and a display plugged in is covered by the
  backdrop until its client makes a surface for it.

=gowl_compositor_lock_session= is the single entry point --- the =lock=
keybind action, =gowl-msg lock=, the idle timer and the suspend path all
call it --- and falls back to a lock-handler module when no
=lock-command= is configured or it will not start, because a lock that
quietly does nothing is the one failure a lock must not have.

*** logind

=src/core/gowl-logind.c= is the seat side: the three things
systemd-logind expects of a graphical session, and which gowl did none
of.

1. *Lock before sleep.* logind announces a suspend and then suspends, so
   a session that merely listens is racing the kernel. gowl takes a
   =delay= inhibitor at startup and holds it; on =PrepareForSleep(true)=
   it locks, waits (bounded, four seconds) for the lock to actually be
   up, and only then releases the fd. On resume it takes it again.
2. *=loginctl lock-session= / =unlock-session=*, which arrive as
   Lock/Unlock signals on this process's own session object.
3. *=SetLockedHint=*, so =loginctl show-session= agrees with the screen
   --- only when gowl owns the seat session, since a nested gowl shares
   the host desktop's session object.

Threading mirrors the notification daemon: GDBus wants a GMainContext
and the compositor's loop is a =wl_event_loop=, so the bus lives on its
own thread and wakes the compositor thread through an eventfd on the
Wayland loop. That makes it work identically under standalone gowl and
under =cmacs --gowl=, where the compositor thread is the one holding the
dispatch lock. =GOWL_DISABLE_LOGIND=1= --- or =GOWL_DISABLE_SYSTEMD=1=,
which every test sets --- skips it.

** The Wayland socket outlives the compositor

=wl_display_add_socket_auto= creates =$XDG_RUNTIME_DIR/wayland-N=, and
libwayland removes it in =wl_display_destroy= -- which neither gowl's
=main()= nor cmacs reaches: both =exit()= with the compositor still
alive.  So without help the file survives every quit, for the rest of
the boot.

That leftover is not merely untidy.  Nothing about a socket file says
whether anything is behind it, so any code that tests for the file --
=access(F_OK)=, =g_file_test= -- reads a dead session as a live one.
cmacs did exactly that when deciding nested-vs-seat, and the effect was
delayed by one login: a cmacs session left its socket behind, the next
launch found the file, forced =WLR_BACKENDS=wayland=, failed to connect
to a socket with nothing on the other end, and died before drawing
anything.  Logging into another desktop and out again "fixed" it,
because that desktop's clean shutdown removed its own socket.

Two pieces address it, in =src/util/gowl-wayland-socket.c=:

- =gowl_wayland_socket_unlink_on_exit()=, called right after the socket
  is created, removes it at =atexit= time -- doing what
  =wl_display_destroy= would have done.  It is a no-op in a forked
  child (the pid is recorded), because there the parent is still
  serving that socket.  The =.lock= file is deliberately left alone:
  it carries no data, the next compositor =flock=s it in place, and
  removing one from under a compositor that holds it would let two bind
  the same name.  Best-effort: =atexit= does not run for a process
  killed by a signal, so this reduces leftovers rather than abolishing
  them -- which is why it is not the load-bearing half.
- =gowl_wayland_socket_live()= answers the question the file cannot, by
  connecting.  Use it instead of a stat wherever "is a compositor
  running on this display" is the actual question; =$WAYLAND_DISPLAY=
  is subject to the same staleness, since it is imported into the
  systemd user manager at session start and nothing unsets it at
  session end.
- =gowl_wayland_detect_parent_session()= applies that to the whole
  environment, and is where the *direction* of the answer is decided.

*** Three answers, not two

A probe can also fail to reach a verdict: no =$XDG_RUNTIME_DIR= to
resolve a relative name against, a path too long for =sockaddr_un=, an
exhausted fd table.  Folding that into "nothing is there" is more
dangerous than the original bug, because the variables this evidence
feeds are exactly what =gowl_systemd_should_manage_session()= reads.
Concluding "no parent" while nested inside GNOME makes gowl start
=gowl-session.target= and, on the way out, stop
=graphical-session.target= --- which is GNOME's, and stopping it ends
the user's entire desktop.  That has happened once already (=e4164d4=).

Hence the deliberately awkward pair =gowl_wayland_socket_live()= /
=gowl_wayland_socket_absent()=: both are false when the probe reached no
verdict, so a caller cannot read uncertainty as either answer by
checking only one of them.  =detect_parent_session= errs toward "there
is a parent", which costs a nested compositor nothing.  The reverse
holds for =$DISPLAY=, where *keeping* it is the cautious choice, so only
a display proven dead (the plain =:N= form, no socket in
=/tmp/.X11-unix=) is cleared.

The tests for this are the ones to keep: =/wayland-socket/detect/=
covers a live parent, a stale one, and two different ways for a probe to
be inconclusive --- each asserting the environment is left untouched.

=tests/test-wayland-socket.c= covers the stale case specifically --
a test that only checks a live socket passes just as happily against
=access(F_OK)=.

** wlroots Version Abstraction
:PROPERTIES:
:CUSTOM_ID: wlroots-version-abstraction
:END:
gowl builds against wlroots 0.19 or 0.20, selected at build time (newest
present by default; =make WLROOTS=0.19= to pin -- see the build guide).
Because the two are ABI-incompatible, a build links exactly one; runtime
"both at once" is impossible (every wlroots compositor pins one version
per build).  What gowl provides instead is a clean *capability* seam:

- =src/gowl-wlroots-compat.h= turns the build-time version
  (=GOWL_WLROOTS_VERSION_{MAJOR,MINOR}=, defined by config.mk) into
  feature flags -- =GOWL_HAVE_WLROOTS_0_20=, =GOWL_HAVE_CAPTURE_WINDOW= --
  so no other file hard-codes a version number.
- Version-specific behaviour lives behind GObject interfaces, not
  =#ifdef= scattered through the compositor.  Screencast capture is the
  first such seam (=GowlCaptureProvider=): the monitor path compiles on
  both versions, the window path is =#if GOWL_HAVE_CAPTURE_WINDOW= inside
  the single provider implementation, and the compositor only ever calls
  the interface.

This keeps Fedora 42/43 (0.19) and Fedora 44+/Ubuntu-from-source (0.20)
on one codebase, with capabilities adapting to whatever is compiled in.

*** Input, as configured
The keymap is built by =build_keymap()= from the =xkb-*= keys (a keymap file, else rules/model/layout/variant/options, else the environment) and applied to the keyboard group and every keyboard =gowl-input-config.c= tracks. Per-device libinput settings from the =input:= section are applied by the same file when a device appears and again on reload. Key modes, bind flags, pointer binds and gestures all end in =run_keybind_entry()=: one function runs an action whatever bound it, so =dispatch_key()= (mode, lock and press/release filtering), =dispatch_mousebind()= and =dispatch_gesture()= only decide whether a bind matched. A finger count with a configured gesture is claimed before the module gesture handlers, like a module claimant, and summed until the gesture ends.

** Screen Sharing (the gowl ScreenCast portal, and portal-wlr)

Screen capture is abstracted behind the =GowlCaptureProvider= GObject
interface (=src/interfaces/gowl-capture-provider.h=), so the compositor
wires capture without naming any wlroots type or version.  The concrete
provider, =GowlCaptureWlroots= (=src/core/gowl-capture-wlroots.c=), is
selected by the compiled wlroots (see [[#wlroots-version-abstraction]]):
it always provides monitor capture, and adds window capture on 0.20+.
It reports a =GowlCaptureCapability= bitmask, surfaces sources as the
=GowlCaptureSource= boxed type (kind/id/title/app_id), and emits
=source-added= / =source-removed= as windows map and unmap.

Screen capture for apps (Zoom, OBS, browsers) goes through
=xdg-desktop-portal-wlr=, which talks to gowl over wlroots protocols.
The provider advertises the globals the portal needs:

- =zwlr_screencopy_manager_v1= -- the actual frame capture path.
- =zwlr_output_manager_v1= (=wlr-output-management=) -- so the portal can
  *enumerate outputs* for the "what to share" picker.  Gowl creates the
  manager (=output_mgr=), publishes the current configuration on startup
  and on every layout change
  (=gowl_compositor_publish_output_config=), and answers the manager's
  =apply= / =test= requests by driving the =gowl_monitor_set_*= mutators.
  Without a published configuration the picker has no outputs to list and
  never appears.
- =xdg_activation_v1= -- lets clients request focus for a surface
  (=request_activate=); gowl focuses the requesting toplevel if it is a
  non-embedded client, else marks it urgent.

Selection of the wlroots portal backend is environment-driven (see the
=XDG_CURRENT_DESKTOP=/=:wlroots= note above), not a gowl protocol matter.

*** Sharing one window

portal-wlr can only offer whole outputs, because =wlr-screencopy= addresses outputs: "share this window" in a video call means sharing the screen it is on and everything else there with it. gowl's own backend exists for that one reason.

The standard =ext-image-capture-source-v1= makes an =ext_foreign_toplevel_handle= a capture source, and gowl already advertises it along with =ext-image-copy-capture-v1= and the toplevel list (=gowl_capture_provider_create_globals=, wlroots 0.20+). =tools/xdg-desktop-portal-gowl= binds all three as an ordinary Wayland client and implements =org.freedesktop.impl.portal.ScreenCast= on the bus name it already owns:

- =portal-capture.c= is the Wayland half: it lists outputs and mapped toplevels, opens a capture session on the chosen one, and copies each frame into a buffer the caller supplies.
- =portal-pw.c= is the PipeWire half: the buffers PipeWire allocates are memfds, each wrapped as a =wl_buffer= over a =wl_shm= pool, so a frame is copied once -- by the compositor -- straight into the memory the application reads. Frames are requested only when PipeWire returns a buffer, so a consumer that stops reading stops the capture rather than building a queue.
- =portal-screencast.c= is the D-Bus half: =CreateSession=, =SelectSources=, =Start=. The chooser is an external dmenu-style command (=$GOWL_PORTAL_CHOOSER=, else the first of bemenu/fuzzel/wofi/rofi/dmenu found), because this process has no toolkit and the session already has a menu.

Two things are easy to get wrong here and are both asserted by tests. The capture session's =shm_format= carries a *wl_shm* enum, not a DRM fourcc -- they agree except for ARGB8888 and XRGB8888, which are 0 and 1 -- and getting it wrong yields a stream that negotiates cleanly and shows the wrong colours. And the session's first size event arrives while the PipeWire stream is still being constructed, so the size callback has to tolerate not having one yet.

The backend declines the interface when PipeWire is absent or the compositor offers no image-copy-capture, and the frontend then falls back to portal-wlr, so a session missing either is no worse off than before. =tests/test-portal-screencast.sh= drives the whole handshake against a headless compositor on a private bus; =tests/test-portal-guard.sh= asserts the window path specifically, since a backend that bound only the output source manager would pass everything else while being a worse portal-wlr.

** Input Capture & Injection (deskflow / KVM)
:PROPERTIES:
:CUSTOM_ID: input-capture-arch
:END:
Gowl implements the freedesktop *InputCapture* and *RemoteDesktop* portals
natively (the generic =xdg-desktop-portal-wlr= backend does not provide them).
The split keeps gowl core free of D-Bus and libeis:

- *gowl core* carries a D-Bus-free state machine, =GowlInputCapture=
  (=src/core/gowl-input-capture.c=), with two boxed value types
  =GowlInputZone= / =GowlInputBarrier=. It enumerates capture zones from
  monitor geometry, validates/stores pointer barriers, detects barrier
  crossings in =motionnotify=, and diverts pointer/keyboard input to a sink
  while active. The five input hooks (=motionnotify=, =on_cursor_button=,
  =on_cursor_axis=, =on_kb_key=, =on_kb_modifiers=) are guarded by the active
  flag, so a non-capturing session is unchanged.
- A gowl-private Wayland protocol, =gowl-input-capture-unstable-v1=
  (=protocols/gowl-input-capture-unstable-v1.xml=, server glue in
  =src/protocols/gowl-input-capture-protocol.c=), exposes zones/barriers,
  the captured-input event stream, and an inject sub-object (driving the
  =wlr_virtual_pointer= / =wlr_virtual_keyboard= globals) to a single trusted
  client.
- =xdg-desktop-portal-gowl= (=tools/xdg-desktop-portal-gowl/=) is a standalone
  binary (links no libgowl) that binds the private protocol as a Wayland
  client, runs a *libeis* EIS server, and owns
  =org.freedesktop.impl.portal.desktop.gowl=. It is built only when
  =libeis-1.0= is present. Full reference: [[file:input-capture.org][Input
  Capture & Injection]].

** Input Recording (teach-a-task)
:PROPERTIES:
:CUSTOM_ID: input-recording-arch
:END:
=GowlInputRecorder= (=src/core/gowl-input-recorder.c=) is the *observing*
counterpart to the injection helpers: a bounded ring of real key and
pointer events, so a human demonstration can become a reusable
procedure.  Like =GowlInputCapture= it links no wlroots and no Wayland
-- the compositor feeds it finished values and the three facts its
suppression policy needs -- which is what makes the policy testable
without a compositor.

Four properties are load-bearing rather than incidental, and each has a
test in =tests/test-input-recorder.c=:

- *Its own consent gate.*  =input-recording= (default =false=) is
  separate from everything that gates injection.  An agent allowed to
  click must not thereby be allowed to watch you type.
- *A ring that reports what it dropped.*  Never grows; =dropped= and
  =dropped_total= are in every payload, because a silently truncated
  demonstration teaches half a task.
- *It stops itself.*  A =wl_event_loop= timer for =max_seconds=, plus a
  deadline re-check at every entry point.
- *Two clocks.*  Recorded events carry wall time and an offset from the
  recording's start, and deliberately no compositor event timestamp --
  the injection helpers stamp synthetic events from the same monotonic
  clock real ones arrive on.

The taps sit on the =wlr_cursor= and keyboard listeners, which the
injection helpers bypass, so gowl's own synthetic input is never
recorded.  A red frame is drawn around the whole layout for as long as
a recording runs, and =Super+Shift+Escape= stops one without its token.

*The protection gowl cannot offer* is a compositor-side notion of a
password field: Wayland gives a compositor no window-internal
knowledge.  The lock screen and an app-id/title deny list are what
exist.  Full reference, including exactly where that stops:
[[file:input-recording.org][Input Recording]].

** Keyboard Focus Arbitration
:PROPERTIES:
:CUSTOM_ID: focus-arbitration
:END:
Every keyboard-focus change in gowl passes through a single gate,
=gowl_compositor_focus_client=, which asks =gowl_focus_decide()=
(=src/core/gowl-focus-rules.c=) whether the change is permitted.  The
rules module is pure logic -- no wlroots, no GObject -- so the whole
truth table is unit-tested in =tests/test-focus-rules.c=; the
compositor only gathers the inputs.

Guards, in escalating order of authority.  The first that fires
refuses the change and names itself in the debug log
(=G_MESSAGES_DEBUG=gowl=):

| Guard                              | Refuses when                                                  |
|------------------------------------+---------------------------------------------------------------|
| =GOWL_FOCUS_DENY_LOCKED=           | A session lock owns the outputs.                              |
| =GOWL_FOCUS_DENY_EMBEDDED=         | The target is an embedded client (host-driven; see below).    |
| =GOWL_FOCUS_DENY_LAYER_GRAB=       | A keyboard-interactive layer surface holds the keyboard.      |
| =GOWL_FOCUS_DENY_EXCLUSIVE_CLIENT= | An X11 override-redirect popup holds an exclusive grab.       |

*** The two exclusive grabs

Gowl tracks two independent "this surface owns the keyboard, leave it
alone" grabs, because the two surface kinds are different types:

- =GowlCompositor.exclusive_focus= (=GowlClient *=) -- an X11
  override-redirect popup.  See [[#xwayland-override-redirect][XWayland
  Override-Redirect]] below.
- =GowlCompositor.exclusive_layer= (=GowlLayerSurface *=) -- a
  keyboard-interactive layer-shell surface: a launcher (wofi, rofi), an
  on-screen keyboard.  Set by =gowl_compositor_arrangelayers()= when it
  hands the surface the keyboard; cleared on unmap, on destroy, and on
  session lock.

=gowl_layer_takes_keyboard()= decides which layer surfaces qualify:
*mapped*, non-zero =keyboard_interactive= (both =EXCLUSIVE= and
=ON_DEMAND= count), at layer =TOP= or =OVERLAY=, and the session not
locked.  Bars and wallpapers sit below =TOP= and so can never take the
keyboard from a window.

The grab is re-derived from live surface state on every check rather
than trusted from the stored pointer, so a surface that unmaps or
commits =keyboard_interactive = 0= releases it on the spot; a missed
clear cannot wedge the keyboard.  The pointer is still cleared on
teardown, because reading a freed =GowlLayerSurface= is not an option.

A focus *clear* (target =NULL=) is refused by the grab guards too --
clearing focus out from under a launcher leaves it just as deaf as
pointing the keyboard at another window does.

When the grab holder goes away, =arrangelayers= re-runs: any other
keyboard-interactive surface still up on that monitor takes the
keyboard, otherwise it returns to the topmost client.

*** Contract for embedders

An embedder that moves seat keyboard focus itself, rather than through
=gowl_compositor_focus_client()=, bypasses every guard above.  cmacs
=--gowl= does exactly this -- embedded clients are deliberately absent
from the compositor's focus stack, so it calls
=wlr_seat_keyboard_notify_enter()= directly to hand keys to Emacs on a
prefix key.

Such code *must* call =gowl_compositor_has_exclusive_keyboard_layer()=
first and do nothing when it returns =TRUE=.  Skipping the check
produces a launcher that is mapped, drawn on top, covering the output,
and completely deaf: the user can neither type into it, nor dismiss
it, nor see that anything else is responding.  Under =emacs --gowl=
this was reproducible by opening =wofi --show drun= within a few
milliseconds of any focus-restoring command.

=tests/test-close-guard.sh= caps the number of
=wlr_seat_keyboard_notify_enter= call sites inside gowl so new
seat-focus paths cannot slip in unreviewed; cmacs carries the matching
assertion for its own sources in
=test/cmacs/cmacs-gowl-tests.el=.

*** Gamma control and the frame commit

=wlr-gamma-control-v1= is what =gammastep=, =wlsunset= and every other
night-light program drives.  Without the global they do not merely
fail to tint the screen --- they report that the compositor does not
support gamma control and exit.

The protocol part is a global and one handler.  The interesting part
is the frame path.  A gamma ramp cannot be committed on its own: it
goes into the same =wlr_output_state= as the frame.  So
=on_monitor_frame()= builds the state explicitly ---
=wlr_output_state_init=, =wlr_scene_output_build_state=, optionally
=wlr_gamma_control_v1_apply=, =wlr_output_commit_state=,
=wlr_output_state_finish= --- rather than calling the one-shot
=wlr_scene_output_commit()=, which is that sequence with no
opportunity to add anything.

Not /quite/ that sequence, though: the one-shot call first asks
=wlr_scene_output_needs_frame()= and returns if nothing on the output
changed, and =wlr_scene_output_build_state()= does not ask --- it renders
and attaches a buffer every time. On DRM every committed buffer is a page
flip, and every page flip ends in another frame event, so a frame handler
that commits unconditionally redraws an idle output at full refresh,
forever; the first version of this path did exactly that. So
=on_monitor_frame()= makes the check itself: it draws only when
=wlr_scene_output_needs_frame()= says so or a ramp is waiting
(=gamma_dirty=). Everything that wants a frame --- damage, a surface's
frame callback, a screencopy, an export-dmabuf or image-capture client,
a software cursor --- sets =needs_frame=, and the scene answers that by
scheduling one. A frame event with nothing to draw still runs the
effects' =frame= and =frame_done= hooks and sends frame callbacks, but
commits nothing and does not emit =GowlCompositor::frame-rendered=, and
an output nothing asks to redraw sends no more frame events at all.
Whatever needs a steady stream from an unchanging screen asks for each
next frame itself, from =frame-rendered=; the recording module does,
while it records. =tests/test-idle-output.c= holds all of this.

The handler therefore cannot apply the ramp itself.  It sets
=gamma_dirty= on the monitor and calls =wlr_output_schedule_frame()=.
That second call is not optional: an otherwise idle output would never
redraw, and the ramp would sit unapplied until something else damaged
the screen --- which is precisely the case that matters, because a
night-light program sets gamma on a screen nobody is touching.

A ramp the hardware will not accept gets
=wlr_gamma_control_v1_send_failed_and_destroy()= rather than being
dropped, so the client learns the screen is not warm instead of
believing that it is.

The API is identical between wlroots 0.19 and 0.20, so unlike the
capture protocols this needs no entry in =gowl-wlroots-compat.h=.

*** Layouts

Layouts live in a registry keyed by name. Each shipped layout is a
plugin: =tile=, =monocle=, =float=, =scrolling=, =centeredmaster= and
=fibonacci=. The compositor dispatches placement to the selected
=GowlLayoutProvider=; layout algorithms and their geometry helpers
reside in =modules/=, not =libgowl=.

A monitor stores the *name* it selected, not an index.  A layout module
loading or unloading therefore cannot leave a monitor pointing into a
changed array, and =gowl_layout_unregister()= moves any monitor using
the departing layout back to the first one.

Two functions exist because a module layout could not otherwise do its
job: =gowl_compositor_place_client()=, since
=gowl_client_set_geometry()= only writes the struct and a layout
calling it would compute a perfect arrangement that reached no client;
and =gowl_monitor_get_compositor()=, since the interface hands a layout
a monitor and placing anything needs the compositor.  Widening the
interface signature was the alternative, and every existing
implementation would have had to change for it.

Each arrangement reads the full logical geometry of its own monitor.
The shared module helper =modules/layout-axis.h= selects portrait only
when height exceeds width; usable-area insets do not affect orientation.
Tile uses its top/bottom split in portrait, while centered-master and
Fibonacci transpose their placements. Scrolling uses the current axis
for placement, gaps, focus visibility and the saved offset (the legacy
=scroll_x= field). Output-layout changes retain the previous usable area
until layer arrangement compares it with the new area, ensuring resize
and rotation trigger placement even without bars or exclusive zones.

**** The scrolling layout

A niri-style strip: full-height columns laid left to right on landscape
and square outputs, or full-width rows running top to bottom on portrait
outputs. The viewport scrolls along them instead of squeezing windows to fit.  =scroll-column-width= (default 0.5, so two are visible) matches
Hyprland's =scrolling.column_width=, which is what Omarchy configures,
so a config translates.

=gowl_compositor_scroll_to_client()= moves by the smallest amount that
reveals a window and does nothing when it is already visible ---
otherwise every focus change would scroll the strip.

Layout algorithms, including the traditional tile, monocle and float
layouts, live in individual modules. The registry stores active provider
references and selection per monitor/tag view. =GowlLayoutProvider=
exposes arrange, focus-client, scroll and overflow hooks. Core placement
and viewport clipping support those hooks; layout geometry is owned by
the plugin. A change in effective layout emits monitor and compositor
=layout-changed= signals after arrangement, which the optional
=layout-indicator= plugin uses for its non-interactive toast.

*** Host close protection

=gowl_client_close()= emits the compositor's =client-close-request=
signal before sending a protocol close. A handler returning true vetoes
the request and stops further handlers. Without a handler, standalone
Gowl retains its normal close behavior. CMacs compares the client's peer
PID with its own PID to protect its hosting windows, and emits
=toast-requested= with a monitor and message. The indicator plugin owns
the presentation; the guard works even when that plugin is disabled.

*** Animation

The engine lives in =modules/animation/=, built as =animation.so=.
=libgowl= contains only the generic =GowlSceneEffect= interface and
=src/core/gowl-effects.c= dispatch bridge. The module owns all easing,
clocks, impulses, surface snapshots, closing ghosts, and per-client
animation state. Existing =GowlConfig= properties remain the settings
API; they do not activate an engine without a loaded module.

The scene-effect providers receive geometry, reveal, release, unmap,
destroy, pre-frame, frame-done, and monitor-removal hooks, and hear of
every frame a window is drawn at --- each hook dispatched as described
under *Six providers, dispatched per event* below. Opacity and displayed
geometry queries keep decorators and input consistent with the
provider. Without a provider, geometry is
immediate. Disabling the animation module finishes motion, restores
live content and opacity, and releases all closing buffers. Shutdown
finishes effects before renderer teardown, and after that nothing is
dispatched to a provider at all: teardown still unmaps and destroys
every client, and a provider woken for those would be working on a
compositor already being finalized.

*GPU reset.* When wlroots reports the renderer lost (=events.lost=: a GPU
reset, or the device going away) the compositor swaps in a new renderer
and allocator on the next loop iteration --- never inside the signal,
which can arrive in the middle of a render pass, where destroying the
renderer fails wlroots' no-listeners-left assert. It makes the new pair
first, so a failure leaves a compositor that cannot draw but is still
alive; asks every effect provider to let go of its GL objects and
buffers (the =finish= hook, with dispatch left open, so providers
rebuild lazily on the new renderer); moves the =lost= listener across;
points surface uploads and every output the scene renders to at the new
pair --- the monitors, and the private output each window screencast
renders through, which would otherwise draw its next frame with a freed
renderer; and only then destroys the old one.

That destroys every texture made with the old renderer, and a texture is
often the only copy of its pixels: a scene buffer releases its
=wlr_buffer= once uploaded. So the swap puts pixels back. The solid lock
backdrop covers the screen again while an animated one waits for a new
frame on every monitor, so a reset while locked never shows the desktop.
The cursor image is re-applied, and the pointer re-entered so a client
sets its own cursor again. Then =GowlCompositor::renderer-replaced= tells
the modules that draw into scene buffers of their own to redraw them;
the wallpaper, bar, rounded borders and lock prompt do. A client window
that has not drawn since the reset reappears on its next commit.
=tests/test-gpu-reset.c= loses a real headless compositor's renderer ---
twice, with a window capture running and the screen locked --- and then
again with those modules loaded, checking that nothing they drew is left
blank.

*Six providers, dispatched per event.* Every hook is either CONSUMABLE
(=client_event=, =get_geometry=, =surface_at= --- first claimant wins,
because two modules cannot both decide where a window is) or BROADCAST
(=alpha_changed=, =frame=, =frame_done=, =monitor_removed=, =finish=,
=client_placed= --- every provider gets one, because a module that misses
its own teardown leaks buffers into a departing renderer, and one that
decorates a window has to follow it whoever moved it).
=src/core/gowl-effects.c= owns that distinction and =tests/test-effects.c=
pins it; both failure modes are silent absences rather than crashes.

*Where a window is drawn is news to every provider.* Placement arrives
as =GEOMETRY=, which is consumable, and the animation module claims it
for every tile --- so a provider sorted after it that only decorates the
window never heard of a resize. The blur module's shadow kept the old
size and its backdrop the old crop after every animated re-tile (Super+h,
a neighbour closing, any layout change) until something else happened to
wake it, and a window that shrank drew them across its neighbour.
=gowl_compositor_apply_frame_geometry()= is the one function every drawn
frame passes through --- the compositor's own placement, the claimant's,
each step of an animation and the step that lands it, whether it draws
rect borders or calls the decorator --- so it ends by broadcasting
=client_placed=, with =settled= TRUE once the window is drawn at its own
geometry and no provider presents it at another (=get_geometry= claims
nothing), FALSE on the steps in between. Expensive work waits for
=settled=: the blur module crops its backdrop to the drawn frame at every
step and stretches the shadow it has over it, draws the shadow again only
once the window has landed, and gives the scene a new backdrop buffer
only when the wallpaper was blurred again, because setting one drops the
texture made from the last. The rounded borders never had the gap: a
decorator is called from that same function. =tests/test-blur-nodes.c=
resizes a window with the animation module loaded, with and without the
rounded borders, and holds both nodes to the drawn frame at every step.

*DESTROY means two things.* It follows UNMAP when a window closes, by
which time the window's scene tree is gone; and the compositor also sends
it, tree staying, to reset a window's effects when it takes the window
over as an overlay, shows it in a panel or gives it back. A provider that
hangs nodes off the client's tree therefore follows each node's own
destroy signal and destroys whatever is still alive, instead of assuming
either case. The blur module used to merely forget its shadow and
backdrop, which left a tile-sized pair hanging off every window that went
through the scratchpad, drawn across the next column of the panel ---
another pair per trip. =tests/test-blur-nodes.c= makes those trips
against the real module.

gowl handed the whole interface to the single highest-priority provider
until there were enough effect modules for that to hurt, at which point
every module after the first would have had to be forwarded to by hand,
eight hooks at a time. =gowl_module_manager_get_scene_effects()= returns
the whole active set in priority order;
=gowl_module_manager_get_scene_effect_after()= remains for a module that
wants to ask what is below it without receiving the call.

*** Visual effect layer

=src/fx/= is the toolkit the effect modules are built on:
=gowl_fx_gl_*= (borrowing the renderer's EGL context, textures, a styled
quad pass, a separable blur), =gowl_fx_pass_glass()= (one ray traced
through a bevelled slab of glass, per pixel), =gowl_fx_pass_water()= (the
same through a moving water surface), =gowl_fx_vis_*= and
=gowl_fx_capture()= (rendering an output as it WOULD look under a
different set of visible windows, and putting the scene back), and
=GowlFxSheet= (one opaque monitor-sized buffer parked in the scene for as
long as an effect owns that output).

It adds no renderer. =libgowl= must stay free of one
(=tests/test-no-libregnum.sh=), and this stays inside that rule by
borrowing the context wlroots' own GLES2 renderer already owns:
=wlr_gles2_renderer_get_egl()= for the context,
=wlr_gles2_renderer_get_buffer_fbo()= for a target, each bracketed by
make-current and restore because that context is process state shared
with wlroots. Under any other renderer =gowl_fx_gl_new()= returns =NULL=
and every module declines to run.

Three invariants hold across all seven callers:

- *Y is negated in the projections.* wlroots hands out a buffer whose
  first row is the top of the picture while GL's first framebuffer row is
  the bottom, so =gowl_fx_mat4_perspective()= and =gowl_fx_mat4_ortho()=
  both negate Y and the default screen quad puts the image's top at
  NDC -1. They have to agree, or one effect comes out upside down while
  the rest look right.
- *There is no depth buffer.* A wlr_buffer's framebuffer has colour only,
  and attaching depth to a framebuffer wlroots owns would be reaching
  into its state. Effects draw back to front and reject back faces on the
  CPU.
- *A capture is a lie that must be taken back.* =GowlFxVis= remembers
  every scene node an effect switched off so one call restores them all,
  including on every early return.

=tests/test-fx-render.c= checks the orientations, the blur and the corner
rounding against a real GLES2 renderer, and skips when there is no DRM
render node. =tests/test-glass-render.c= does the same for the
refraction: that it builds at all, that the flat centre of a slab passes
a ray straight through, that the rim samples INWARD, that the corners are
cut out, and that a tilted surface catches light. Every one of those can
be wrong in a way that still looks plausible --- a lens that bends
nothing is indistinguishable from a frosted backdrop, and one that bends
the wrong way is indistinguishable in a screenshot and wrong over text.

*The tube is the only whole-output filter.* =gowl_fx_pass_crt()=
(=src/fx/gowl-fx-crt.c=, driven by =modules/crt=) is the one effect here
that does not draw behind a window: it captures the finished output and
draws the whole of it back through a curved faceplate, a scanned beam, a
phosphor mask and halation. Two things in =src/fx/= exist for it.

=GOWL_FX_SHEET_FILTER= marks a sheet as a picture of the desktop AS IT
IS, put through a shader and parked on top, rather than a picture of some
other state. It does two things.

=gowl_fx_capture()= hides every such sheet for the length of its render,
which is what stops the tube photographing its own last frame --- and,
just as important, stops the magnifier, the cube and the switcher
building their pictures out of an already-curved one and putting a second
tube through it.

And a filter sheet *declares no opaque region, and is allocated with an
alpha channel it never uses*. Both are needed to stop wlr_scene
concluding that it occludes what is under it --- it infers opacity from
the buffer's format before it looks at any region --- and that conclusion
is fatal for a sheet that stays up. wlr_scene culls damage from nodes it
can prove are hidden and sends frame callbacks only to visible surfaces,
so a permanently parked opaque full-screen sheet tells every window on
the machine that it cannot be seen: they stop scheduling frames, they
stop receiving callbacks, and they stop drawing. The screen then holds
the picture that was captured when the sheet went up, the compositor
sits at no CPU, and nothing is logged --- it reads exactly like the
editor having hung, and the editor is fine.

The hint would be a lie in any case: a filter sheet is made OF the things
it covers, so they have to keep drawing for it to have anything to
photograph. The cost is that the scene below it is composited rather than
culled, which is a second pass over a scene the capture has already
drawn. tests/test-crt-frames.c holds both halves.

=GOWL_FX_SHEET_ABOVE_OVERLAY= parks a sheet above every layer a client
can be in, and unlike the other placements it hides NOTHING. The others
switch off the clients they cannot cover --- fullscreen and
embedder-pinned ones --- which is right for an effect that captured the
screen once at the start and wrong for one that re-captures every frame:
a client switched off to make room would be missing from that capture,
and a fullscreen video would simply vanish. The session lock layer stays
above it either way.

The glass and water programs are the two things =gowl_fx_gl_new()= does
NOT build up front. Each is compiled on first use and its failure is
survivable (the pass returns =FALSE= and the module shows nothing),
because building them eagerly would let a driver that chokes on one
=atan= take the cube, the overview, the switcher, the magnifier and the
blur down with it.

*** Injected input takes the same path as real input
:PROPERTIES:
:CUSTOM_ID: injected-input-path
:END:

=gowl_compositor_inject_key()= and =gowl_compositor_inject_button()= go
through =compositor_handle_key()= and =compositor_handle_button()= ---
the same functions the physical devices reach --- and *not* through
=wlr_seat_*_notify_*=.

This is not tidiness.  A key handed straight to the seat arrives at the
focused client and at nothing else: no configured keybind, no module
keybind, no embedder intercept.  A click handed straight to the seat
reaches whatever surface is under the cursor, which never includes the
bar, because a bar draws scene buffers the compositor hit-tests itself.

Both used to do exactly that, and the result was a software KVM
(deskflow driving this machine through the RemoteDesktop portal) that
could type into applications and click inside them, while *every*
compositor binding and the whole bar were dead --- from the remote
keyboard and mouse only.  From the physical ones everything worked, so
it read as a deskflow fault rather than a gowl one.  Nothing is logged:
the input arrives, applications respond, and only the compositor's own
surfaces are inert.

Three things are skipped for synthetic input, and they are the only
differences:

- *the recorder tap*, so gowl never records its own injections --- a
  synthesiser reading that trace would be replaying its own output;
- *the InputCapture diversion*, which would send a key or click we were
  just handed straight back out to whoever sent it;
- *key repeat*, because the sender is already repeating, and adding ours
  double-fires the binding for as long as the remote holds the key.

Injected *motion* needed no change: it already moved the real cursor
through =gowl_compositor_motionnotify()=, which is why hover worked from
the remote pointer while clicking did not, and why the hit tests are
looking in the right place by the time a button arrives.

=tests/test-inject-routing.sh= fails the build if an injector talks to
the seat directly again.  =tests/test-record-guard.sh= enforces the
recorder half at the tap now rather than by keeping injection away from
it --- the old arrangement relied on the bypass that *was* the bug.

*** A captured image that outlives the frame needs a buffer we own
:PROPERTIES:
:CUSTOM_ID: fx-buffer-ownership
:END:

=gowl_fx_capture_to_buffer()= hands back a slot of the *output's*
swapchain.  Presenting it and dropping it inside one frame is fine.
Keeping it is not, for two reasons, and the second is the dangerous one:

- it takes a buffer permanently out of the rotation the output needs to
  present; and
- it ties the content to a pool the compositor keeps drawing the live
  desktop into.  If that slot is ever handed back out --- a swapchain
  recreated on a mode or format change, a lock dropped, a scanout path
  that does not consult the lock --- what you are holding stops being
  your capture and silently becomes a photograph of the desktop, windows
  and all.

The blur backdrop did exactly this.  It captured the wallpaper with
every client layer hidden, which is correct, and then held the output's
buffer for as long as the tag set did not change --- which in frame
terms is forever.  The symptom was a translucent window on one tag
showing *another tag's application* through it, intermittently: what a
stale desktop frame looks like when it reappears underneath something
see-through.

Anything that needs a captured image to outlive the frame allocates its
own =wlr_swapchain=, as =GowlFxSheet= always has and the blur backdrop
now does.  =tests/test-fx-buffer-ownership.sh= fails the build on a new
caller of =gowl_fx_capture_to_buffer=, because there is currently no
legitimate one.

*** A sheet is not in a layer, and a capture must hide it
:PROPERTIES:
:CUSTOM_ID: fx-sheet-capture
:END:

=GowlFxSheet= parks its tree as a *direct child of =scene->tree=* --- a
sibling of the layer trees, not inside one --- so an effect can place it
above or below whole layers.  That placement has a consequence which is
easy to miss and produces a convincing-looking rendering bug.

An effect that wants to see *past* the windows hides the client layers:

#+begin_example
gowl_fx_vis_hide_layer(vis, self, GOWL_SCENE_LAYER_TILE,  FALSE);
gowl_fx_vis_hide_layer(vis, self, GOWL_SCENE_LAYER_FLOAT, FALSE);
...
#+end_example

That sweep cannot reach a sheet, because a sheet is not in any of them.
And a sheet is not decoration: it is an *opaque, monitor-sized picture
of the desktop with its windows in it*, left in the scene by the cube,
expo or switcher for as long as that effect owns the output.

So a capture taken while one is parked captures the sheet.  The blur
module builds its frosted backdrop exactly this way --- wallpaper only,
every client layer hidden --- and caches the result per monitor, keyed
on the tag set.  Rebuild it during a tag switch, while the cube's sheet
is up, and the backdrop becomes a blurred picture of *the tag being
left*, stamped as current for the tag being entered.  On screen: a
translucent terminal on tag 2 showing ghosts of a chat window from
tag 4, persisting until something else invalidated the cache.

Every such capture must therefore also call:

#+begin_example
gowl_fx_vis_hide_sheets(vis);
#+end_example

which walks the live-sheet registry (=gowl_fx_sheet_live()=, maintained
in =gowl_fx_sheet_new()= / =_free()=) and switches each tree off for the
duration of the capture.  =tests/test-fx-sheet-guard.sh= fails the build
if a file that hides =GOWL_SCENE_LAYER_TILE= does not also hide sheets.

**** Announce visibility changes only once the monitor has settled

A related ordering rule, in =gowl_compositor_arrange()=.  Tag visibility
is applied in *two* passes: first every client's scene node is enabled
or disabled, and only then is =GOWL_SCENE_EFFECT_REVEAL= announced for
the ones that appeared.

One pass would announce a reveal while clients later in =self->clients=
still carried their previous visibility --- and an effect handling
REVEAL may capture the output, which would then contain whichever
windows the loop had not reached yet.  The failure depends on list
order, so it presents as intermittent.

*** A source box outside its texture aborts the session
:PROPERTIES:
:CUSTOM_ID: fx-source-box-invariant
:END:

=wlr_render_pass_add_texture()= asserts that the source rectangle lies
inside the texture:

#+begin_example
src.x >= 0 && src.y >= 0 &&
src.x + src.width  <= texture->width &&
src.y + src.height <= texture->height
#+end_example

An assert here is not a debug aid.  It aborts the process, on the
compositor thread, in the middle of a page flip.  Under =cmacs --gowl=
that process is the user's entire desktop session, and because Emacs
re-raises the fatal signal on its main thread the crash is reported with
an *idle pselect backtrace* that names nothing to do with rendering.
Diagnosing one costs a core dump.

So anything calling =wlr_scene_buffer_set_source_box()= owns that
invariant.  Two rules follow.

**** Never derive a source box from =c->geom=

=GowlClient.geom= is the *layout's* idea of where a window is, and it is
routinely not on the output:

- a layout that allows overflow (scrolling) leaves it unclipped on
  purpose --- it is the window's place in a strip wider than the screen,
  and =gowl_compositor_clip_client_geometry()= moves the *scene node* to
  the on-screen intersection while =geom= keeps the full rectangle;
- a floating window dragged half off the monitor is never clipped at
  all.

Use =GowlClient.frame=, which =gowl_compositor_apply_frame_geometry()=
records: the frame as actually drawn, in layout coordinates.  This is
exactly the bug that killed a session --- the blur module cropped its
backdrop with =c->geom=, and a window at x=2848 with width 1376 on a
2880-wide output asked for pixels 4224 columns in.

**** Intersect, then clamp

Intersect the frame with the monitor before scaling into buffer pixels,
and clamp the result to the texture afterwards.  The intersection makes
the invariant true in exact arithmetic; the clamp absorbs what a
fractional output scale leaves behind.  Clamping the width alone is not
enough --- a window scrolled off the *left* edge fails the =src.x >= 0=
clause instead.

=modules/blur/gowl-blur-geom.c= is that calculation, deliberately split
into a pure translation unit so =tests/test-blur-geom.c= can assert the
invariant directly, including a sweep over every position a window can
take relative to a monitor.  Scale each axis from its own extent: a
width-derived vertical scale is only correct while the output's pixels
are square.

=src/util/gowl-backdrop-plan.c= is the same calculation one layer up,
shared by every backdrop that renders per window rather than cropping one
shared picture. It is split out for the same reason and one more: these
work in THREE
coordinate systems at once --- layout for where the window is, the
output's device pixels for the wallpaper it bends, and the render
buffer's own pixels, which are the device ones divided by however far the
render was scaled down while the window was moving. Getting one of those
conversions wrong does not abort; it refracts the top-left quarter of the
wallpaper, which is the kind of mistake that survives review.
=tests/test-backdrop-plan.c= asserts each conversion separately.

The other place a source box crosses a boundary is
=modules/animation/gowl-scene-snapshot.c=, which copies one verbatim ---
and may be copying the *surface's* current buffer rather than the scene
node's, which can be a different size.  It clamps to the buffer it
actually uses.

*** Touchpad gestures

=GowlGestureHandler= offers swipes and pinches to modules BEFORE they are
relayed to the focused client. It is consumable and the claimant is
remembered for the whole gesture rather than re-asked per update: a
handler that stopped claiming halfway would drop the rest of the swipe
into the client mid-motion. A claimed gesture is one the application
never sees, which is the point --- a three-finger swipe that turned the
desktop and also scrolled the browser underneath it is nobody's intent
--- and it is why a handler that cannot act must decline in =begin=
rather than claim and do nothing.

The cube claims three fingers; expo claims four.

*** Module commands

A module =.so= cannot export a function for the compositor to call, so it
exports a NAME. =gowl_compositor_run_command()= offers a command word to
the =GowlIpcHandler= modules and then announces it on the IPC socket, and
it is the one entry point shared by the =ipc_command= keybind action, the
socket, and an embedder --- so
=@{ action: ipc_command, arg: "expo" @}= opens the overview without gowl
knowing an overview exists.

Modules also see key RELEASES, not only presses. The interface always
carried a =pressed= flag and it has to mean something: an alt-tab
switcher is held open by a modifier and commits when it is let go, which
cannot be built from presses alone. Configured keybinds are still
consulted first and still only on press, so this cannot shadow a user's
binding.

*** Desktop cube

=modules/cube/= turns the desktop as one side of a solid when the tag
changes, one face-step per tag crossed. It splits three ways:
=gowl-cube-plan.c= decides what turns and for how long and links no
wlroots or GL, so the arithmetic is testable headless;
=gowl-cube-gl.c= draws a frame and knows nothing of the compositor; the
module file connects them and owns every side effect.

It adds no renderer. =libgowl= must remain free of one
(=tests/test-no-libregnum.sh=), and the cube stays inside that rule by
borrowing the EGL context wlroots' own GLES2 renderer already owns:
=wlr_gles2_renderer_get_egl()= for the context,
=wlr_gles2_renderer_get_buffer_fbo()= for a target, both bracketed by
make-current and restore because the current context is global state
shared with wlroots. Under any other renderer =gowl_cube_gl_supported()=
is false and the module declines, leaving tag switches instant.

Sides are captured with =wlr_scene_output_build_state()= after the
scene's client visibility has been set to each tag in turn --- once,
when the rotation starts, and restored immediately. There is no depth
buffer: a wlr_buffer framebuffer has colour only, and a convex solid
with back faces rejected on the CPU does not need one, provided the draw
order stays backdrop, reflection, cap, sides.

The rotation is presented as a single opaque monitor-sized
=wlr_scene_buffer= placed above =GOWL_SCENE_LAYER_FLOAT=, so it hides the
layers below by covering them rather than by disabling them --- the
layers are global while tags are per-monitor, and disabling one would
blank a second output. Clients gowl stacks ABOVE that point (fullscreen,
and embedder-pinned overlay clients) are hidden individually for the
duration and restored from a held reference, so a window closed
mid-rotation cannot leave a dangling one.

Geometry animations interpolate the whole rectangle. A snapshot of the
client's surface tree preserves buffer source rectangles, transforms and
relative offsets; each frame scales both positions and sizes together.
The client receives only its final configure, then the snapshot gives
way to the live tree. Frame callbacks keep that hidden tree rendering;
hit-testing translates pointer coordinates through the displayed scale.
Closing snapshots do not intercept input. Pure moves keep live content
when jiggle strength is zero; squash/stretch otherwise uses a snapshot.

Openings use their own duration and curve. The opacity clock is shorter
and cannot overshoot. Closings own a snapshot independently of the
client, so teardown cannot invalidate the buffers being displayed.
Closing during a morph transfers that snapshot at its current size and
opacity. Embedded clients do not use snapshots.

=on_monitor_frame= advances animations before rendering and schedules
another frame only while an animation is live on that output; with
nothing live and nothing changed, it draws nothing at all (see /Gamma
control and the frame commit/). Repeated
arrangements with the same destination retain the current clock; a new
destination retargets from the displayed rectangle. Interactive moves
and resizes remain immediate while the pointer is held. Releasing a
changed window starts a bounded, decaying squash/stretch impulse around
its final rectangle. Openings and layout transitions apply the same
two-cycle impulse on top of their easing; exits use one squeeze cycle.
The impulse starts and ends at zero and never changes layout geometry.
Embedded and fullscreen clients do not jiggle.

Curves are cubic Béziers. Bisection solves the parameter for a given
elapsed-time fraction before evaluating the curve's progress.

*** Liquid glass
:PROPERTIES:
:CUSTOM_ID: liquidglass-architecture
:END:

=modules/liquidglass/= shows a translucent window the wallpaper as it
would look through a slab of glass shaped like the window: flat in the
middle, rounded off over a bevel at the edge. The optics are in
=src/fx/gowl-fx-glass.c=; the module is bookkeeping.

*It is not a blur with a highlight painted on.* One ray is traced per
pixel through one surface, and every feature of the rim falls out of it
--- how far the picture is pulled, where it darkens, where the light
sits, how wide the colour fringe is. That is why it holds together at any
size and around the corners, where a painted rim does not. The
arithmetic follows [[https://github.com/VII-Cae/hyalite--liquid-glass][hyalite]] (MIT), which worked it out for the web out of
SVG displacement maps; three of its findings are repeated in the source
because each is invisible there and obvious on screen (the direction
field comes from a WIDER rounded rect, geometry scales while optics does
not, and a decay slope above 1 folds the field on purpose).

*It and the blur are alternatives, not layers.* Both put one scene node
in the same place in the same window's tree, so both drawing means one is
hidden behind the other while both still pay for a capture and a blur on
every tag switch. =window-backdrop= in the config picks one, both modules
read it, and =GOWL_ACTION_CYCLE_BACKDROP= --- =Super+Shift+"= --- moves
it and re-places every window so each module hears to add or drop its
node. That re-placement is the whole mechanism by which the key is
instant; without it the change would not appear until each window was
next moved.

*The cost model differs from the blur's in one way that shapes the
module.* A blur backdrop is a crop of one shared picture, so a window
that merely moved re-points its crop and is correct. Glass bends the
wallpaper behind THAT window, so a window that moved is refracting
somewhere else and must be drawn again --- one fragment-shader pass over
the window. Three things keep that affordable: a window at rest is drawn
at full device resolution and one still moving at half
(=GOWL_GLASS_MOVING_DIVISOR=), a move of less than one texture pixel is
not a move (=gowl_glass_render_stale()=), and each window owns a small
=wlr_swapchain= so a frame is never drawn into the buffer the scene is
still reading from. A render that fails leaves the last picture up: a
missed frame is invisible, a window that goes clear for one frame is not.

*The look is compared with memcmp, not field by field.* =reload_config=
can change any of a dozen settings, every window's render depends on all
of them, and a comparison that forgot one would leave untouched windows
showing the old look until they next moved --- a bug that appears only
after a reload and only on the windows nobody is looking at.

*** Liquid water
:PROPERTIES:
:CUSTOM_ID: liquidwater-architecture
:END:

=modules/liquidwater/= shows a translucent window the wallpaper through a
moving surface. The optics are in =src/fx/gowl-fx-water.c=; the module is
the part that is different from every other backdrop, and all of the
difference is one word: MOVING.

*The other backdrops settle and this one never does.* The blur draws a
crop of one shared picture; the glass draws a window's own picture and
redraws it when the window moves. Both are, between events, correct and
free. This one is stale the moment it is drawn, which forces three things
nothing else here needs --- a clock, a frame rate, and an honest
admission about power.

*The clock is four phases, not a time.* A seconds-since-start float loses
its mantissa: after an hour a 32-bit float resolves about a quarter of a
second and the waves visibly stutter. Wrapping it instead jumps every
wave at once, because the four run at incommensurate rates and no wrap
point is a whole number of cycles for all of them. So each phase is
accumulated in a double and handed over already wrapped into [0, 2pi) ---
exact in a float, forever, with no jump. That is also why nothing in the
height field is evaluated outside a sine: an earlier version warped the
domain with value noise, which is periodic on the integer lattice and not
at 2pi at all, and every wrap would have snapped the whole surface
sideways. It is ONE clock for the whole desktop, not one per window: two
windows side by side are two holes in the same pond.

*It advances against the wall, not once per output.* With two monitors
the frame hook runs twice a frame, and advancing the clock in each would
run the water at double speed on a two-screen desk.

*The surface is two-dimensional by construction.* The obvious build --- a
sum of directional sine waves --- does not work, and no retuning fixes
it: a sine varies along one direction and is constant along the other, so
a few of them summed and lit give regular parallel bands. The window came
out looking like brushed metal. What is used instead (Alekseev's
=Seascape=, MIT) takes =1 - |sin|= along each axis and MULTIPLIES them,
which is a field of cells rather than a set of bands.

*Two things about that construction have to be worked around.* Its
octaves are non-negative, so the surface needs centring or "how high is
this crest" --- which is what the foam threshold asks --- means nothing.
And =1 - |sin|= has a kink wherever the sine crosses zero, whose second
derivative is a spike: sampled a pixel and a half apart the Laplacian
found those spikes and drew them, covering the window in a grid of white
crosses. The sampling step scales with the wavelength so it steps OVER
the kinks and measures the curvature that is actually there.

*The frame hook is the pump, and =client_placed= is the bootstrap.*
Returning TRUE from =frame= is what asks for another frame on that
output, and it is returned exactly while there is water to draw. But an
output with nothing changing on it has already stopped scheduling frames,
so nothing would ever start the clock; drawing from =client_placed=
damages a scene node, which is what makes the output ask for a frame.
Without it a window that became translucent on a still screen would sit
there with no water.

*** A dragged window and the rate its backdrop is drawn at
:PROPERTIES:
:CUSTOM_ID: backdrop-drag-rate
:END:

Every per-window backdrop redraws from =client_placed=, which runs once
per POINTER MOTION EVENT while a window is being interactively moved or
resized. A mouse reports at up to a thousand hertz and a screen shows
sixty, so fifteen out of every sixteen of those renders were thrown away
before anyone saw them.

*And =settled= cannot be used to notice.* It is FALSE while a provider
is animating the window and TRUE otherwise --- and during a drag nothing
is animating it, the pointer is moving it directly. So it was TRUE
throughout every drag, and the liquid glass's half-resolution
=GOWL_GLASS_MOVING_DIVISOR=, written for exactly this, never applied to
the one case it was most obviously for.

*The render was not even the expensive half.* An interactive resize
changes the buffer size on every one of those events, and
=gowl_backdrop_plan= handing back a different =buf_width= throws the
render swapchain away and allocates a new one --- several buffers the
size of the window, a thousand times a second. That is what made a
floating window with an animated backdrop behind it go to treacle under
Super+right-drag.

=gowl_compositor_client_is_grabbed()= is what a provider asks, and the
two kinds answer it differently because they have different machinery:

- The five ANIMATED backdrops do nothing at all on a =client_placed= for
  a grabbed window. Their frame hook redraws it anyway, once per output
  frame, and a window that has just moved makes the plan stale so the
  frame-rate throttle does not skip it either. The drag then costs what
  it was always going to cost once per frame instead of once per input
  event.
- The liquid GLASS has no clock and no frame hook --- it is event-driven
  because between events it is correct --- so skipping the event would
  freeze it for the whole drag. It keeps drawing and counts the time
  itself, at most once every eight milliseconds, which is above any
  refresh rate anybody has and below every mouse report rate. It also
  takes the moving divisor now, which is what that constant was for.

The BLUR needs none of this: its backdrop is a crop of one shared
output-sized picture, so a window moving re-points a source box and
allocates nothing.

*While the glass is throttled it keeps the source box it was DRAWN
with,* and that is not tidiness. The new plan's box is in the new
buffer's coordinates, and handing wlroots a source box past the end of
the buffer it actually has is an abort rather than a glitch --- gowl has
taken a whole session down that way before.

=tests/test-blur-nodes.c= asserts it by watching the node's dest size
across eight simulated motion events. Not by watching which BUFFER the
node points at, which is the obvious thing and passes either way: a
resized render destroys the swapchain and allocates a new one, and the
allocator hands the same addresses straight back.

*** Windows that get no effects at all
:PROPERTIES:
:CUSTOM_ID: fx-optout
:END:

=src/util/gowl-fx-optout.c= answers one question --- should this window
have effects --- and =gowl_compositor_apply_fx_optout()= asks it once,
in the map path, before any module has seen the client.

*It sets the rule flags, not a flag of its own.* =GOWL_CLIENT_RULE_NO_BLUR=,
=NO_SHADOW= and =NO_ANIM= are already honoured by every backdrop module,
the shadow and the animation, so nothing downstream had to learn about
this: a Steam game and a window covered by a =no-blur= rule look
identical to the modules, which is right, because they want the same
thing. It only ever ORs, so a rule that switched something off is never
switched back on.

*The answer comes from the PROCESS, which is why it is not a window
rule.* Three inputs:

- =/proc/PID/environ= for =GOWL_NO_FX=, read from the client's process
  rather than from the compositor's own environment. That is what makes
  it inherited --- export it and everything started from that shell is
  covered --- and it is the reason this cannot be expressed in a config
  file at all.
- The same block for Steam's markers (=SteamAppId=, =SteamGameId=,
  =SteamClientLaunch=, =STEAM_COMPAT_DATA_PATH=), which is how a game
  whose executable nobody could name is recognised.
- The window's =app_id=, and the command name of its process and of
  every ancestor, against a built-in list (=steam=, =steamwebhelper=,
  =mutter-devkit=) plus the configured =no-fx-apps=.

*The ancestry walk stops at the compositor's own pid,* and that stop is
load-bearing rather than an optimisation. gowl is embedded in cmacs and
cmacs is started from a shell; a walk that ran to pid 1 would find
=sh=, =systemd= and whatever else is above the compositor for EVERY
window, so naming any of them would switch the effects off across the
whole desktop instead of for one program.
=tests/test-fx-optout.c= has a case for that direction specifically,
built on a spawned grandchild so there is a real process tree to walk.

Reading =/proc= can always fail --- the process exits between the map
and the read, a container hides it, a hardened kernel refuses it --- and
every failure answers "leave the window alone", which is the state the
desktop was in before this existed.

*** A floating window drawn behind the tiling
:PROPERTIES:
:CUSTOM_ID: window-below
:END:

=GOWL_SCENE_LAYER_FLOAT= sits above the whole of =GOWL_SCENE_LAYER_TILE=,
so "floating" and "on top" are the same statement and there is no
ordering within FLOAT that puts a floating window behind a tiled one.
=client->isbelow= is drawn by moving the window's tree into the TILE
layer and lowering it there, while everything else about it stays
floating: it is not in =gowl_compositor_tiling_clients()=, it keeps its
own geometry, and no layout places it.

Two functions carry it. =client_scene_layer()= is the whole decision ---
fullscreen, floating-and-above, otherwise the tiling layer --- and
=client_restack()= re-parents and then lowers. Everything that used to
spell the layer choice out (=setfloating()=, =setfullscreen()=,
=arrange()=) calls them, which is what keeps a sunk window sunk through
a re-tile: =arrange()= puts every client back in its layer, and what
that used to mean was "every floating window into FLOAT".

*Focus does not raise it.* The window keeps the keyboard while it is
down, which is what makes pressing the same key again bring it back
without hunting for the window first --- so the raise in
=gowl_compositor_focus_client()= is skipped for it. Two sunk windows
therefore keep their relative order: there is no "top of the bottom" to
raise to, and lowering the newly-focused one would put it under the
other.

=tests/test-window-below.c= asserts the layer AND the order, because
either alone passes for a broken version: the right order in the FLOAT
layer is still drawn over every tile, and the right layer without the
lowering is drawn over them too. It establishes which end of a
=wlr_scene_tree='s child list is the top against
=wlr_scene_node_raise_to_top()= rather than assuming it, since the
header does not say.

*** One host for four backdrops
:PROPERTIES:
:CUSTOM_ID: backdrop-host
:END:

=src/fx/gowl-fx-backdrop-host.c= is the half of an animated backdrop
that is not optics: the clock, the per-output frame throttle, the
wallpaper capture taken with the windows hidden, the per-client
=wlr_swapchain= and scene buffer, the weak compositor reference and a
teardown that survives the renderer going away underneath it.

*It exists because there were five copies of it.* =liquidwater=,
=liquidrain=, =fizz=, =leaves= and =snow= each carry their own, roughly
eight hundred lines apiece, and they have already had to be fixed in
lockstep more than once --- the interactive-drag rate fix went into all
five by hand. Four more effects would have been four more copies.

=modules/soapfilm=, =modules/embers=, =modules/submerged= and
=modules/dew= use it instead, and each is about 390 lines: a settings
struct, a config read, a clock advance and a draw call. What a module
supplies is a =GowlBackdropHostVTable= --- its name, the
=GowlBackdropStyle= it draws for, the sizes of its settings and clock
structs, and three callbacks.

*The settings struct must begin with a =GowlBackdropHostCommon=.* That is
a blunt contract and a deliberate one: the host needs four integers (the
fps throttle, the render scale, and the two blur parameters for the
source) out of a void pointer, and the alternative is four accessor
callbacks per effect to fetch four integers. The host compares the whole
struct with =memcmp()=, so every field in it has to be part of what "the
look" means.

*The five older ones are NOT ported.* They work, they are tested, and
rewriting working code to prove a point is how a refactor becomes a
regression. They can move one at a time, and the host was derived from
=modules/fizz= so the move is mechanical when somebody wants it.

*** The colour that is computed rather than sampled
:PROPERTIES:
:CUSTOM_ID: soap-interference
:END:

=src/fx/gowl-fx-soap.c= is the only shader here whose output colour is
not taken from anywhere. Every other one moves the wallpaper's colour
around, tints it, or scatters it; this one computes a colour from a
thickness:

: R(lambda) = 4 R0 sin^2(2 pi n d / lambda),   R0 = ((n-1)/(n+1))^2

*The headline feature is a LIMIT.* As d goes to zero the phase goes to
zero and sin² of it goes with it, for every wavelength at once --- so the
film stops interacting with light. In reflection that is the famous black
film a bubble shows before it bursts; in transmission, which is what a
window does, the top of an old film simply goes clear. It is not drawn
in. Nothing else in this directory has a headline that falls out of the
arithmetic going to zero.

*One presentational choice, and it is named in the shader.* A real film
reflects at most nine percent, so its honest effect on a view through it
is a few percent of dimming and a few percent of chroma --- invisible
behind a translucent window. The transmission's exposure is normalised
out and its chroma is kept, which is what =soap-gain= then amplifies. It
preserves the limit above: at d → 0 every channel's transmission is 1,
the mean is 1, and the division changes nothing.

*** Absorption is not a tint
:PROPERTIES:
:CUSTOM_ID: submerged-absorption
:END:

=src/fx/gowl-fx-submerged.c= has no blue in it. The colour comes from
three per-metre absorption coefficients and one exponential, with red
attenuating about twenty times faster than blue --- so depth walks the
picture through the sequence a diver sees rather than fading it towards a
hue. The same exponential runs the other way for the light scattered INTO
the line of sight, which is what keeps distant things pale instead of
black.

The caustic net is the edges of a cellular field whose feature points
ORBIT rather than translate. That is not decoration: a caustic is the
fold line of the map from a wavy surface to the bottom, which for a
random surface is exactly the boundary between the regions each bump
lights --- and the waves pass through rather than carrying the pattern
with them, so it writhes in place. A translating pattern reads as a
scrolling texture, which is what a periodic sine version of this looks
like.

*** Two mechanisms the embers brought
:PROPERTIES:
:CUSTOM_ID: embers-blackbody
:END:

=src/fx/gowl-fx-embers.c= is the only EMISSIVE backdrop --- its subject
adds light rather than bending it --- and it carries two things nothing
else here does.

*The palette is a cooling curve.* The colour of a spark is the Planckian
locus at its current temperature, evaluated directly, and its brightness
is the FOURTH power of that temperature (Stefan-Boltzmann). A spark that
has cooled by half is sixteen times dimmer, which is why real ones wink
out sharply rather than fading. The reference temperature is a constant
in the shader and not the configured one: dividing by the knob would
normalise the knob away, and a fire set to 1200 K would be exactly as
bright as one set to 2400. That was a real bug, caught by the test that
measures the ratio.

*The heat haze is a domain warp.* Every other displacement in this
directory comes from the geometry of a surface --- a lens, a slab, a
height field. Hot air is a turbulent mixture of refractive indices, so
what it does to a view through it is to displace the sample by a
smoothly varying, slowly drifting random field. Straight lines wobble
rather than bending one way, and the envelope fades upward because the
plume spreads and mixes itself away.

*** The same optics somewhere else entirely
:PROPERTIES:
:CUSTOM_ID: dew-placement
:END:

=src/fx/gowl-fx-dew.c= reuses the rain's thin-lens arithmetic unchanged
--- a dew drop and a raindrop are the same ball of water --- and is a
different effect because of where the drops are: threaded onto an orb
web rather than scattered over a pane.

*One thing that had to be kept apart, and was not at first.* A bead is
shaped in the THREAD's frame, along it and across it, because surface
tension draws it out lengthwise. The lens displaces what is behind it in
the SCREEN's frame. The spiral runs in a different direction at every
point, so using the thread coordinates directly as a screen offset sends
the image sideways by an amount that depends on where round the web the
bead sits --- which looks like a lens everywhere except where you check
it. The test that reads the sign of a ramp's slope inside the beads
caught it.

*** The disc that a blur is not
:PROPERTIES:
:CUSTOM_ID: bokeh-kernel
:END:

=src/fx/gowl-fx-bokeh.c= is the blur module's other kernel, and it is a
second kernel rather than a ninth module precisely because the product is
the same: one output-sized picture of the wallpaper that every window
crops a piece out of. The blur module grew a =GowlBlurKernel= it compares
with =memcmp()= and a generation counter on each backdrop, because
before that the only things that made a backdrop stale were its size and
its tags --- so switching between blur and bokeh changed nothing on
screen until the next tag switch.

Three things separate it from a Gaussian and two of them are not the
shape. The kernel is a disc or a polygon. The averaging is done in LIGHT
rather than display values, which are encoded with roughly a square root.
And bright samples are weighted up, because a wallpaper has no values
above 1.0 to carry the dynamic range a real lens works with --- without
that the discs are all drawn and none of them are visible, which is the
failure mode that makes people conclude bokeh does not work on SDR
images.

*** The three weathers that are not liquid
:PROPERTIES:
:CUSTOM_ID: weather-backdrops
:END:

=modules/snow/=, =modules/leaves/= and =modules/fizz/= are the other
three animated backdrops, drawn by =src/fx/gowl-fx-snow.c=,
=gowl-fx-leaves.c= and =gowl-fx-fizz.c=.

*The host half is the rain's, written out three more times.* The clock,
the per-output frame throttle, the wallpaper capture with the windows
hidden, the per-client =wlr_swapchain= and scene buffer, the weak
reference to the compositor and the teardown are the same problem
whatever the shader draws, and every word of
[[#liquidwater-architecture][the water's section]] about them applies
unchanged. Each
module carries its own copy rather than inheriting one: what that buys is
that a shader can be added or removed without touching the other four,
and what it costs is that a fix to the host half has to be applied five
times. =tests/test-compositor-teardown.c= loads all five, because each
has its own chance to reach a freed compositor on the way out.

What follows is only what is genuinely different.

**** A bubble is a diverging lens

Every other backdrop in the tree bends light the same way: liquid in gas,
converging, and past a certain depth INVERTING --- which is the most
recognisable thing a raindrop does. A gas bubble in liquid is the other
sign. It minifies, it is a tiny fisheye, and it never inverts however
large it gets.

That is one character in the displacement, so it is asserted rather than
commented. =tests/test-weather-render.c= puts a horizontal RAMP behind
both shaders at the same depth --- so the rendered value at a pixel says
where in x the shader sampled --- and reads the sign of its local slope.
The bubbles come out four to one upright-and-steeper; the drops better
than two to one reversed. Neither count is ever zero, because every lens
of either kind reverses the gradient along its own antialiased rim, so
the test is on each lens's own BALANCE of the two rather than on a
comparison between them.

The other half of a bubble's optics is not a knob either: light inside
the liquid meeting the wall past the critical angle is totally reflected,
and =sin(theta_c) = 1/1.333 = 0.75=, so the silvered ring starts at
exactly three quarters of the radius. It is why bubbles read as rings
rather than as dots.

**** A train is indexed by emission number

The rain's running drops are one drop per column per cycle, found by
=fract()= of the column's clock. A nucleation site emits a FILE of
bubbles, several of which are on screen at once, so a pixel cannot ask
"which drop is here" --- it has to ask "which of the several".

It works out the phase a bubble at this pixel's HEIGHT would be on and
turns that into the emission that would be there now, then checks three
either side. That inverse exists because the rise itself is a closed
form: a bubble grows as it rises and its speed goes as the square of its
radius, so =dh/dt = c(1 + g*h)^2=, which integrates and inverts. Growth,
acceleration and the widening of the gaps up a train all fall out of the
one number.

The consequence is a new rule. The emission index is the clock times the
column's rate times its bubbles per cycle, so both of those have to be
WHOLE numbers or the index does not change by a multiple of the cycle
count when the clock wraps --- and every train would jump once a wrap.
The cycle count is also smaller than the rain's, 64 rather than 256,
because the integer being hashed is now up to =cycles * 3 * 8= rather
than the clock itself.

**** A leaf is opaque, and that changes the whole shader

There is no displacement in =gowl-fx-leaves.c= and no surface normal. A
leaf covers the wallpaper rather than bending it, and the only thing that
saves it from being a brown sticker is that it is BACKLIT: the wallpaper
comes through it tinted and DIFFUSED, and the venation shows dark because
a vein is thicker tissue that passes less light.

Sampling the sharp wallpaper for that term is the obvious thing to write
and it prints the desktop onto the leaf, which is exactly how it looked
before the term was moved to the blurred source.

The leaf's own silhouette is three shapes, because one is a logo. The
maple is a polar profile, since a maple really is radial --- five lobes
spreading from the point where the stem joins, and the sinus falls out of
the phase rather than being carved. The oak is NOT: pinnate lobing runs
down either side of a midrib, and a polar profile gives a lobed disc
however much it is elongated, which is a flower. It is the ovate profile
with its half-width rippled along the blade instead.

*The tumble is worth more than every other cue put together.* A falling
leaf turns about its long axis and twice a turn presents its edge,
collapsing to a LINE. Nothing else on a screen does that. It is one
multiply --- the blade squashed across by =|cos(tumble)|= --- and its
sign says which face is towards the viewer, so the paler underside is
free and makes the tumble legible as a turn rather than as a narrowing.

**** The wind is one number on the CPU

Every leaf on every screen reads the same gust, and that is the whole
reason a gust looks like ONE gust rather than like each leaf
independently deciding to leave. It also carries the releases: a stuck
leaf's adhesion is hashed per tenure and the gust pulls its release point
EARLIER, so a gust takes several leaves at once and calm air takes almost
none --- correlated departures with no state anywhere.

It is one slow sine modulated by two slower ones and then squared. Both
halves of that are load-bearing. A SUM of three sines is a poor gust,
because three things that rarely agree spend nearly all their time
cancelling; the first version was exactly that and produced a wind that
sat at a quarter strength forever and never once got up. And a sine,
however modulated, spends half its life above the middle of its range,
which is a fan --- squaring is what makes it calm most of the time and
strong briefly. Measured over eleven minutes: below a fifth of full
strength 58% of the time, peaking at 0.87.

The three phases are wrapped at 2pi INDIVIDUALLY. Deriving them from one
accumulator and scaling it is the obvious economy and makes the scaled
values jump at every wrap, because they do not reach a whole turn
together.

**** A settled snowflake is three objects in succession

It lands as a crystal, which SCATTERS --- snow is a foam of ice and air,
so a flake on glass is a bright diffusing patch and not a lens. It melts
into a bead, which is a raindrop and refracts like one. And then it runs,
through what is structurally the rain's =run_layer()= because once a
flake has melted there is nothing snow-specific left to model.

One phase drives the shape (six-fold towards a circle), the size (down by
=snow-shrink=) and the optics (scatter towards lens), which is what keeps
a half-melted flake half-rounded, half-collapsed and half-refracting at
the same instant. The crystal is accumulated SEPARATELY from the water
rather than into the same winner-takes-all: folding both together would
force a half-melted flake to be one or the other, and a half-melted flake
is visibly both.

=snow-shrink= at 0.35 is severe and not severe enough to be wrong; a
snowflake is mostly air. Cross-fading white to clear at a constant size
--- the obvious implementation --- reads as a flake going invisible
rather than as one turning into water.

*Testing that took two attempts and the first is worth recording.*
Walking the settled clock through a life and measuring the pane at eight
points measures NOTHING: every cell carries its own phase offset, so the
population is spread evenly across the whole lifecycle at every instant
and advancing the clock only rotates which cell is where. The aggregate
is invariant by construction, and the eight numbers came out flat to two
significant figures. The test varies =snow-melt= instead, which moves the
whole population to one end or the other.

**** The frost is the one clock that is not wrapped

Ice does not repeat, so =GowlFxSnowClock.frost= saturates rather than
wrapping. What it moves is a THRESHOLD on a warped ridged-noise field, so
lowering it is the growth FRONT advancing --- feathers appear at their
tips and reach inwards. Raising an alpha on a finished pattern is what
frost does not do, and ten seconds of watching tells the two apart.

The ridge is cubed. Without that the field is broad and smooth and the
threshold lets whole REGIONS through, which is not frost but a smudge on
the lens; that is what the first version drew.

*** Graphics tablets

Before =src/core/gowl-tablet.c=, the new-input switch handled
=KEYBOARD=, =POINTER= and =SWITCH=, and every other device type fell
into =default: break;=.  A pen therefore did *nothing at all* under
gowl --- not a stroke, not a click, not even cursor motion --- and
nothing said so.  A silently ignored device produces no warning and no
log line; the only symptom is hardware that appears broken.

Two audiences are served from the same events, chosen per motion:

- a surface that accepts tablet-v2 gets real tool events, with
  pressure, tilt, distance and rotation.  GDK3 binds the whole
  =zwp_tablet_*= family, so this is what carries pressure into a GTK
  client --- cmacs's org-ex ink already reads =GDK_AXIS_PRESSURE= and
  scales stroke width by it, and had simply never received a value
  other than 1.0 under gowl.
- everything else gets *pointer emulation*: the tip is a left click,
  the barrel buttons are right and middle, and motion goes through the
  normal =motionnotify= path so sloppy focus and the cursor image
  behave exactly as they do for a mouse.

The choice is made per event rather than per tool, by asking
=wlr_surface_accepts_tablet_v2()= about whatever is under the cursor.
A pen can therefore cross from an inking buffer onto a menu and keep
working.

Three lists rather than one device: a tablet, its pad, and each tool
the user picks up are separate libinput devices with separate
lifetimes.  Tools are created lazily and cached on the wlroots object,
because libinput reports a tool the first time it is seen and again
every time it returns.

Two details that are easy to get wrong:

- Only the axes flagged in =updated_axes= carry new values.  Feeding a
  stale one back would jitter the stroke, and =NAN= is how
  =wlr_cursor_warp_absolute()= spells "this axis did not change".
- A tool that leaves proximity mid-stroke must be sent an explicit
  *up*.  Nothing else will ever tell the client, which would otherwise
  keep drawing.

The pad is presented to clients but gowl binds nothing to its buttons:
what they should do is a user decision, and the keybind table is where
user decisions live.

=tests/test-input-device-guard.sh= fails the build if the default arm
of the device switch goes back to a bare =break=, because that is
exactly how tablets were lost the first time.

*** Pointer lock and confinement

=pointer-constraints-v1= lets a client ask for the pointer to be
*locked* --- frozen, with no absolute position --- or *confined* to a
region.  =relative-pointer-v1= is what such a client reads instead:
raw deltas, unaffected by the screen edge.

They are one feature rather than two.  Locking without a relative
stream leaves a client with no motion input at all, and a relative
stream without locking leaves the cursor free to walk out of the
window mid-turn.  Together they are what makes an FPS, a VM console,
and an RDP or VNC client usable; without them the pointer escapes the
window and the view stops turning.

The model is one active constraint at a time --- the protocol says so,
and it is the only thing that makes sense for a single cursor.
=constraint_check_surface()= runs from =motionnotify= with whatever
surface is under the cursor, activating that surface's constraint and
deactivating any other.  =on_new_pointer_constraint= additionally
activates immediately when the requesting surface already has pointer
focus, because a client that locks on its own click will never produce
the motion event that would otherwise trigger activation.

In the motion handlers:

- relative motion is sent *first and unconditionally*.  Gating it on
  the cursor actually moving would starve exactly the client that
  asked for the lock.
- a =LOCKED= constraint suppresses =wlr_cursor_move= entirely, in the
  absolute handler as well as the relative one --- a tablet or a VM's
  absolute mouse must not teleport the cursor out from under a client
  holding the lock.
- a =CONFINED= constraint drops motion that would leave the region.

Deactivation has one trap worth naming:
=wlr_pointer_constraint_v1_send_deactivated()= may *destroy* the
constraint, for a =ONESHOT= lifetime.  The stored pointer is therefore
cleared before the call, not after.  A separate destroy listener
handles the constraint going away underneath us, where sending
deactivated would be a use-after-free.

=gowl_compositor_pointer_is_locked()= exposes the state, because a
locked pointer is indistinguishable from a frozen cursor to anyone who
does not know a constraint exists.

*** Embedder-defined keybind actions

The keybind action list is a C enum, so every bind resolves to one of a
fixed set of compositor operations --- or to =spawn=, which launches a
subprocess.  For an embedder that is a poor fit: under =emacs --gowl=
the compositor /is/ the editor's process, and "run this Elisp" was
expressible only by spawning something that talked back over D-Bus.

=GOWL_ACTION_CUSTOM= closes that gap.  A bind carrying it hands its
=arg= string, uninterpreted, to the handler registered with:

#+begin_src C
void gowl_compositor_set_custom_action_handler (GowlCompositor       *self,
                                                 GowlCustomActionFunc  func,
                                                 gpointer              user_data);
#+end_src

The compositor attaches no meaning to =arg= --- deciding what it says
is the embedder's whole job.  cmacs reads it as an Elisp form.

Two properties are deliberate.  With no handler installed the bind is a
no-op, which is the behaviour every gowl before the hook existed had,
so an inherited config does not start erroring.  And the key is
consumed whether or not a handler ran: it matched a configured bind, so
forwarding it on to the focused client would be surprising.

The handler runs on the compositor thread, inside key dispatch, so it
must not block and must not touch anything that is not thread-safe.
cmacs hands the form to the Emacs main loop with =g_idle_add= rather
than evaluating it where it is called: the Lisp VM belongs to that
thread, and blocking the compositor on it would stall every client's
frame callbacks.  The eval that eventually runs is wrapped in cmacs's
=waiting_for_input= guard and a =condition-case=, because an error
escaping into =signal_or_quit()= while the compositor is in input-wait
aborts the process --- and under =--gowl= that process is the entire
session.

*** Invoking a keybind without a key press

=gowl_compositor_dispatch_keybind()= runs the action bound to a
modifier+keysym pair directly.  It is the same function real key
presses go through, so a =custom= bind reaches the embedder and a
=spawn= bind launches its command.

This is deliberately *not* what the input-injection calls do.
=gowl_seat_send_key()=, =gowl_seat_send_text()= and the MCP =send_key=
tool hand a key to the focused client and never consult the keybind
table --- delivering a keystroke to an application is their entire
purpose, and having them also fire compositor binds would make every
injected =Super+q= quit the session.  The two are separate operations
and each has its own entry point.

The practical uses are a menu that offers to run a bind, a cheatsheet
that can invoke what it lists, and tests: nothing else in the tree can
synthesise input that reaches keybind dispatch, so without this the
=custom= path would be unreachable from a test.  cmacs exposes it as
=gowl-run-keybind=.

*** Closing clients

Related, and for the same reason -- one entry point, one set of
guards: =gowl_client_close()= is the only place that may call
=wlr_xdg_toplevel_send_close()= or =wlr_xwayland_surface_close()=.  It
routes via =gowl_close_route_for()=, which picks the protocol from
which surface pointer the client actually carries.  An X11 client's
=xdg_toplevel= is =NULL=, so sending the XDG close to one derefs
=NULL= inside wlroots and takes the compositor down -- and under
=emacs --gowl= the compositor *is* the session, so every application
in it dies too.  =tests/test-close-guard.sh= fails the build if a
second call site appears.

** XWayland Override-Redirect (Unmanaged) Surfaces
:PROPERTIES:
:CUSTOM_ID: xwayland-override-redirect
:END:

X11 *override-redirect* surfaces -- popup menus, combo dropdowns,
tooltips, DND icons, and app confirmation dialogs (e.g. Zoom's "End
meeting / Leave") -- are positioned by the client and must not be tiled,
bordered, or reparented into the managed hierarchy.  Gowl handles them on
a dedicated *unmanaged* path (ported from dwl), distinct from managed
toplevels:

- =client_is_unmanaged()= = X11 surface with =override_redirect=;
  =client_wants_focus()= wraps
  =wlr_xwayland_surface_override_redirect_wants_focus()=.
- On map (=on_client_map=): use the surface's own x/y, float in the
  =FLOAT= scene layer, no border, and -- if it wants focus -- set
  =GowlCompositor.exclusive_focus= and focus it.  The surface is *not*
  added to the client/focus lists and is never arranged.
- =gowl_compositor_focus_client= refuses to focus anything else while
  =exclusive_focus= still wants focus (so the popup keeps its grab --
  the =GOWL_FOCUS_DENY_EXCLUSIVE_CLIENT= arm of =gowl_focus_decide()=,
  see [[#focus-arbitration][Keyboard Focus Arbitration]]), and
  crucially does *not* deactivate the popup's parent toplevel when the
  incoming client wants focus.  Deactivating the parent makes Qt / wine
  treat the popup as dismissed and close it in ~0.5s -- the guard
  (=!client_wants_focus(c)= plus "never deactivate an override-redirect
  old surface") is what keeps the dialog on screen.
- On unmap/destroy: =exclusive_focus= is cleared and focus returns to the
  top managed client.

Set =GOWL_DEBUG_XWAYLAND=1= to log each X11 surface's type
(override-redirect vs managed, with class/title) at =message= level --
the quickest way to confirm which path a given window takes.

** Raw Frame Sink (External Animated Backgrounds)

Gowl can display *externally produced* frames as the wallpaper or the
lock-screen background without rendering them itself and *without depending on
any rendering engine*.  Only a plain pixel span crosses the boundary, so an
outside producer (e.g. a cmacs build rendering libregnum screensavers --- in
cmacs's case from a *separate render process*, streamed in over shared memory)
keeps all of the GL / engine code on its side.

- =GowlRawBuffer= (=src/core/gowl-frame-sink.{c,h}=) wraps a caller-supplied
  =ARGB8888= buffer =(pixels, width, height, stride)= in a =struct
  wlr_buffer=.  The byte order is =DRM_FORMAT_ARGB8888= — little-endian
  =B,G,R,A=, exactly what =glReadPixels(GL_BGRA)= yields, so no channel
  swizzle is needed.  Pixels are *copied*, so the caller may reuse its buffer
  immediately.
- =GowlFrameSink= owns one =wlr_scene_buffer= per monitor on a chosen scene
  layer.  =gowl_frame_sink_push()= creates-or-swaps the per-monitor buffer
  (cheap =wlr_scene_buffer_set_buffer= on re-push); =clear= / =clear_all= tear
  the nodes down.  A =keep_at_bottom= flag lowers each pushed node to the
  bottom of its layer (used for the lock background so the password UI on the
  same layer stays above it).

The compositor exposes this as:

#+BEGIN_SRC c
void     gowl_compositor_push_wallpaper_frame (self, monitor, px, w, h, stride);
void     gowl_compositor_clear_wallpaper_frame(self, monitor);   /* NULL = all */
void     gowl_compositor_push_lock_frame      (self, monitor, px, w, h, stride);
void     gowl_compositor_clear_lock_frame     (self, monitor);
gboolean gowl_compositor_has_lock_frame       (self);
gboolean gowl_compositor_monitor_bg_covered   (self, monitor);
#+END_SRC

- *Wallpaper frames* go on the =BG= layer, drawn *above* the static wallpaper
  image, so clearing them reveals the original wallpaper.
  =monitor_bg_covered= reports whether a monitor's wallpaper is fully occluded
  by a visible fullscreen client, letting an animated producer pause it.
- *Lock frames* go on the =BLOCK= (session-lock) layer, kept beneath the
  password UI; while a lock frame is present the solid lock backdrop
  (=locked_bg=) is hidden so the frame shows through, and the screenlock
  module renders its password surface transparently (so the box, dots, and
  status text composite on top).  =has_lock_frame= is how screenlock knows.

*Invariant:* none of this links =libregnum=, =graylib=, =raylib=, or GL — the
sink sources only wlroots / glib / pixman.  =tests/test-no-libregnum.sh=
(run by =make test=) fails the build if any =lrg_*= / =grl_*= symbol or engine
header ever leaks into =libgowl= or a module.
