* Gowl Configuration Guide
:PROPERTIES:
:CUSTOM_ID: gowl-configuration-guide
:END:
** Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:
Gowl supports two configuration methods that work together:

1. *YAML configuration* -- Declarative config file for all standard settings.
2. *C configuration* -- Compiled config file for full programmatic control.

Both can be used simultaneously. The C config runs after the YAML config, so C values override YAML values.

*** Precedence (lowest to highest)
:PROPERTIES:
:CUSTOM_ID: precedence-lowest-to-highest
:END:
1. Built-in defaults
2. YAML configuration file
3. C configuration module
4. Command-line arguments (=--debug=, etc.)

** YAML Configuration
:PROPERTIES:
:CUSTOM_ID: yaml-configuration
:END:
*** Search Paths
:PROPERTIES:
:CUSTOM_ID: search-paths
:END:
Gowl searches for =config.yaml= in this order (first match wins):

1. =./data/config.yaml= -- Project directory (for development)
2. =~/.config/gowl/config.yaml= -- User config (recommended)
3. =/etc/gowl/config.yaml= -- System-wide config
4. =/usr/local/gowl/config.yaml= -- Installation default

Override the search with =--config=:

#+begin_src sh
gowl --config /path/to/my-config.yaml
#+end_src

*** Generating a Default Config
:PROPERTIES:
:CUSTOM_ID: generating-a-default-config
:END:
#+begin_src sh
gowl --generate-yaml-config > ~/.config/gowl/config.yaml
#+end_src

This writes the built-in default configuration to stdout.

**** compositor
:PROPERTIES:
:CUSTOM_ID: compositor
:END:
General compositor settings.

| Property       | Type   | Default        | Description                                                             |
|----------------+--------+----------------+-------------------------------------------------------------------------|
| =log-level=    | string | ="warning"=    | Log verbosity: ="debug"=, ="info"=, ="message"=, ="warning"=, ="error"= |
| =repeat-rate=  | int    | =25=           | Keyboard repeat rate (keys per second)                                  |
| =repeat-delay= | int    | =600=          | Keyboard repeat delay (milliseconds before repeat starts)               |
| =terminal=     | string | ="gst"=        | Terminal emulator command                                               |
| =menu=         | string | ="wofi --show drun"= | Application launcher command (bound to =Super+p=)               |
| =sloppyfocus=  | bool   | =true=         | Enable sloppy (focus-follows-mouse) focus                               |
| =manage_lid=   | bool   | =true=         | Power off the internal panel (eDP/LVDS/DSI) when the laptop lid is shut and an external display is connected |
| =input-recording= | bool | =false=       | Allow a recording of real key and pointer input to be started.  See [[file:input-recording.org][Input Recording]] |
| =input-recording-deny-apps= | string | ="" | Comma-separated globs; recording pauses while the focused window matches one.  *Added* to the built-in list, never replacing it |

When =manage_lid= is enabled (the default), gowl turns the laptop's
built-in panel off while the lid is closed and at least one external
display is present, moving the selected monitor and any clients to the
external output.  If no external display is connected, the internal
panel stays on so the machine is never left blank.  Closing or opening
the lid at runtime, and hotplugging the external display, are all
handled live.

=input-recording= is deliberately *not* implied by anything that grants
input *injection*.  An agent allowed to click on your behalf must not
thereby be allowed to watch you type, so the injection tools
(=send_key=, =send_text=, ...) and the recording tools
(=start_recording=, ...) sit behind different switches.  Turning this
on is the whole consent step; everything else -- the on-screen
indicator, the bounded ring, the self-stop deadline, and what the
compositor can and cannot recognise as a secret -- is in
[[file:input-recording.org][Input Recording]], which you should read before setting it.

**** appearance
:PROPERTIES:
:CUSTOM_ID: appearance
:END:
Visual appearance settings.

| Property               | Type   | Default     | Description                           |
|------------------------+--------+-------------+---------------------------------------|
| =border-width=         | int    | =2=         | Window border width in pixels         |
| =border-color-focus=   | string | =accent=    | Focused window border                 |
| =border-color-unfocus= | string | =surface=   | Unfocused window border               |
| =border-color-urgent=  | string | =red=       | Urgent window border                  |

The three colours default to palette entry names rather than literals,
so they follow the palette.  See [[#palette][Palette]] --- any colour
setting accepts a literal too.

**** palette
:PROPERTIES:
:CUSTOM_ID: palette
:END:

One set of named colours that every colour setting in the config
resolves against, so the borders, the bar and the lock screen can be
changed together instead of one at a time.

#+begin_src yaml
palette:
  name: latte          # a built-in flavour to start from
  accent: "#d20f39"    # any other key overrides one of its entries

border-color-focus: accent

modules:
  bar:
    bg-color: base/cc  # the same background at 80% opacity
    fg-color: text
#+end_src

A colour setting is one of three things:

| Spec        | Means                                            |
|-------------+--------------------------------------------------|
| ="#rrggbb"= | A literal, used as written.  =#rrggbbaa= too.    |
| =accent=    | A palette entry.                                 |
| =accent/cc= | That entry with its alpha replaced.              |

An unknown name resolves to itself rather than failing the config: far
more likely a colour format the consumer understands and the palette
does not than a typo worth refusing to start over.

Built-in flavours are =mocha=, =macchiato=, =frappe= and =latte= (the
four Catppuccin ones) and =dwm=, which reproduces exactly what gowl
looked like before palettes existed.  All five define the same key set,
so a config written against one renders under any other: =base=,
=mantle=, =crust=, =surface=, =overlay=, =text=, =subtext=, =accent=,
=red=, =green=, =yellow=, =blue=, =mauve=, =teal=, =peach=.

***** Module settings

A module setting is resolved against the palette when its *key* contains
=color= or =colour=.  Module settings are an untyped string map with no
schema, so the key name is the only thing available to decide it --- and
because the decision lives in the config layer, a module written later
gets palette support without knowing the feature exists.  A setting
named anything else (=font=, =height=) is passed through exactly as
written.

***** What is stored

Specs are stored as written and resolved on read.  A generated config
writes =accent= back out, not the literal it currently resolves to ---
a file with today's colours baked into it is one the next palette
change cannot reach, which is the situation this replaced.

**** layout
:PROPERTIES:
:CUSTOM_ID: layout
:END:
Layout engine settings.

| Property  | Type   | Default  | Description                                      |
|-----------+--------+----------+--------------------------------------------------|
| =default= | string | ="tile"= | Default layout: ="tile"=, ="float"=, ="monocle"=, ="scrolling"= |
| =mfact=   | float  | =0.55=   | Master area factor (0.05 - 0.95)                 |
| =nmaster= | int    | =1=      | Number of windows in the master area             |
| =scroll-column-width= | float | =0.5= | Window size as a fraction of usable width (landscape/square) or height (portrait).  0.5 shows two columns or rows, 1.0 shows one.  Matches Hyprland's =scrolling.column_width= |

Layouts adapt to each monitor's current logical dimensions on every
arrangement, including live mode and rotation changes. When height is
greater than width, tile puts the master above the stack (a horizontal
split), scrolling runs top to bottom, centered-master uses a central
horizontal band, and Fibonacci starts with a horizontal split. Square
and landscape monitors keep the normal orientation. Bars and gaps do
not affect this decision, and monitors choose independently. Monocle
still fills the usable area; floating windows retain their positions.
An explicitly enabled =vsplit= continues to select top/bottom tiling
on landscape and square monitors too.

Layouts are plugins. The standalone defaults enable =tile=, =monocle=
and =float=; enable scrolling and the optional layout toast in the
existing module mapping:

#+begin_src yaml
modules:
  scrolling:
    enabled: true
  layout-indicator:
    enabled: true
#+end_src

CMacs loads these modules by default. Its Super+< / Super+> shortcuts
cycle active layouts only on the current tag view. Super+s selects the
scrolling strip and Super+[ / Super+] scroll it. Each tag view remembers
its layout independently.

**** Motion
:PROPERTIES:
:CUSTOM_ID: animations
:END:

Standalone Gowl leaves the animation plugin unloaded by default. Opt in
by adding this to the existing =modules= mapping:

#+begin_src yaml
modules:
  animation:
    enabled: true
#+end_src

=cmacs --gowl= bundles and loads =animation.so= by default, preserving
its window motion. The existing top-level settings below remain valid
for YAML, C config, and GObject/Elisp callers. =animations: true= alone
does not load the plugin in standalone Gowl.

Keyboard focus cycling with Super+j/k gives the newly active window a
small 220 ms wiggle while retaining the focus border color. It does not
change window placement or interrupt an entrance or layout transition.
It follows =animation-jiggle-strength= (0 disables it), and skips
fullscreen and embedded windows.

| Property                   | Type   | Default           | Description |
|----------------------------+--------+-------------------+-------------|
| =animations=               | bool   | =true=            | Animate windows |
| =animation-duration=       | int    | =260=             | Move/resize and release jiggle duration in ms; =0= disables all animation |
| =animation-duration-open=  | int    | =360=             | Entrance duration in ms; =0= disables entrances |
| =animation-duration-close= | int    | =180=             | Exit duration in ms; =0= disables exits |
| =animation-popin-scale=    | float  | =0.84=            | Entrance starting / exit ending scale, from =0.5= to =1.0= |
| =animation-jiggle-strength= | float | =1.0=             | Squash/stretch intensity, =0= off through =2= double strength |
| =animation-curve-open=     | string | ="ease-out-back"= | Entrance geometry curve |
| =animation-curve=          | string | ="ease-out-expo"= | Layout geometry curve |

Open and close durations of =-1= inherit =animation-duration=.

*Opening.* Windows grow from 84% around their center, with an overshoot
and two diminishing squash/stretch bounces. Opacity uses =almost-linear= and reaches the
client's configured alpha within 120 ms (or the entrance duration, if
shorter). This makes the motion visible while the window settles. The
fade applies to the snapshot and borders as well as the live surface.
A client without a capturable buffer fades in without scaling.

*Closing.* The last visible content shrinks toward 84% over 180 ms,
with a quick squeeze and an =almost-linear= fade. It stays above
retiling neighbours. Closing during an entrance preserves the picture,
size and opacity already on screen. Hidden clients do not leave ghosts.
If no buffer remains at unmap, the window disappears immediately.

*Layout changes.* Position, size and borders interpolate together over
260 ms, with a small directional jiggle. Repeating the same destination retains the current animation's
clock; a new destination starts from the displayed rectangle. There is
no vertical rise after a pop or resize completes. Interactive dragging
tracks the pointer directly; releasing a moved or resized window adds a
brief jiggle around its final bounds. Clicking without moving does not
trigger it. Embedded and fullscreen clients do not jiggle, and embedded
clients remain exempt from snapshot resizing.

Snapshots preserve each surface buffer's crop, transform and relative
position, including subsurfaces. The client receives the final size
once; intermediate frames stretch the saved content. Content is frozen
until the animation ends, then the live surface returns. At zero jiggle
strength, a pure move keeps live content without a snapshot. Pointer coordinates are
translated through the displayed scale, and hidden live surfaces continue
receiving frame callbacks so they can render the final size. Closing
snapshots let clicks pass through to surviving windows.

Curves: =linear=, =ease-out-quint=, =ease-in-out-cubic=,
=almost-linear=, =quick=, =ease-out-expo=, =ease-out-back= and =spring=.
The last two overshoot. Layout movement uses =ease-out-expo= with a
bounded jiggle layered on top, so the wobble does not grow with travel
distance. Set =animation-jiggle-strength= to =0= for the original motion,
=0.5= for a softer jiggle, or =2= for double intensity.

Omarchy's Hyprland config uses =popin 87%= with =easeOutQuint= on
entrance and separate opacity timing. For a similar restrained entrance,
set =animation-popin-scale= to =0.87= and =animation-curve-open= to
="ease-out-quint"=, with =animation-jiggle-strength= at =0=. The default
here adds a larger pop and a squash/stretch jiggle for more emphasis.

**** Desktop cube
:PROPERTIES:
:CUSTOM_ID: cube
:END:

A tag switch turns the desktop as one side of a solid rather than cutting
to it. Crossing several tags turns several times and shows each tag on
the way past, so tag 1 to tag 4 is three turns through tags 2 and 3.

Standalone Gowl leaves the plugin unloaded. Opt in through the =modules=
mapping:

#+begin_src yaml
modules:
  cube:
    enabled: true
#+end_src

=cmacs --gowl= bundles and loads =cube.so= by default. The cube and the
[[#animations][animation]] module are designed to run together: the cube owns the
output for the length of a rotation and hands every other decision to the
animation module, so window entrances, exits, layout motion and jiggles
are unchanged with both loaded.

The plugin borrows the compositor's GLES2 context. Under any other
renderer (Vulkan, pixman) it logs a message, stands down, and tag
switches stay instant; nothing else changes. A rotated output also sits
rotations out, because the projection assumes screen-aligned axes.

| Property               | Type   | Default               | Description |
|------------------------+--------+-----------------------+-------------|
| =cube=                 | bool   | =true=                | Master switch; =false= keeps the plugin loaded but silent |
| =cube-duration=        | int    | =520=                 | One turn, in ms; =0= disables the cube |
| =cube-step-duration=   | int    | =150=                 | Added per EXTRA turn, capped at three times =cube-duration= |
| =cube-curve=           | string | ="ease-in-out-cubic"= | Rotation curve, from the same set as =animation-curve= |
| =cube-faces=           | int    | =4=                   | Sides of the solid, =3= to =12=; =4= is a cube |
| =cube-zoom=            | float  | =1.45=                | Camera pull-back mid-turn, =1.0= to =3.0= |
| =cube-pitch=           | float  | =14=                  | Camera elevation in degrees, =-30= to =30=; =0= hides the lid |
| =cube-shading=         | float  | =0.78=                | How dark a side gets as it turns away, =0= to =1= |
| =cube-reflection=      | float  | =0.32=                | Floor reflection strength, =0= to =1=; =0= skips the pass |
| =cube-motion-blur=     | float  | =0.35=                | Directional blur at speed, =0= to =1= |
| =cube-caps=            | bool   | =true=                | Draw the top and bottom of the solid |
| =cube-backdrop-color=  | string | ="#12141f"=           | Colour behind the solid; palette names resolve |
| =cube-all-monitors=    | bool   | =false=               | Also turn outputs that are not the focused one |
| =cube-gesture=         | bool   | =true=                | Drive the rotation with a three-finger swipe |

*How far it turns.* The distance is the difference between the two tag
numbers, with no wrap-around: 9 to 1 is the eight-step trip, because tags
read as a row in the bar and in the head, not as a ring. A tag view
holding several tags at once uses its lowest tag as the ordinal, so
replacing a view turns and merely adding a tag to one does not.

*How long it takes.* =cube-duration= plus =cube-step-duration= for each
extra turn, capped at three times =cube-duration=. A longer journey feels
longer without an eight-tag jump becoming a wait.

*Why it does not cut.* At both ends of the rotation the pull-back, the
pitch, the backdrop and the reflection are all exactly zero, and the
leading side then projects to precisely the viewport --- so the first and
last frames ARE the flat desktop.

*What the camera does in between.* Two things, and only one of them is
=cube-zoom=. The camera is held a fixed distance from the NEAREST SURFACE
of the solid rather than from its axis, so the picture does not swell
every time a corner comes round; =cube-zoom= is the extra pull-back on
top of that. Separately, the rotation pulls back as far as it needs to
keep the whole solid in frame, because tilting the camera over the lid
swings the near bottom edge down the screen. So =cube-zoom: 1.0= is the
tightest framing available rather than literally no camera move, and it
gets tighter again with =cube-pitch: 0= or =cube-reflection: 0=, which
remove the two things that need the room.

*What is on the sides.* Each side is that tag's wallpaper and windows,
captured once when the rotation starts. Layer-shell surfaces above the
tiling layers --- the bar, notifications --- stay live and on top of the
rotation rather than being baked into every side. Clients the embedder
pins over its own surface --- the in-buffer views of =cmacs --gowl=, and
module overlays such as a dropdown terminal --- are not on a tag at all,
so they go onto EVERY side and their live copies come down for the
rotation; gowl parks them above the sheet, so left alone they would hang
motionless in mid-air while the desktop turned underneath.

*Turning it by hand.* With =cube-gesture= on, a three-finger touchpad
swipe turns the solid directly rather than triggering a rotation: the
desktop is exactly as far round as the fingers have pushed it, and
letting go settles to whichever side is nearer --- past halfway it
commits and changes tag, short of it the same rotation runs backwards to
where it started. The drag is deliberately NOT eased. A curve applied to
a direct manipulation makes the desktop lag behind the touchpad and then
catch up, which reads as the machine being slow rather than as motion
design.

A gesture the cube claims never reaches the focused client, which is
right --- a swipe that turned the desktop and also scrolled the browser
underneath it is nobody's intent --- but it means =cube-gesture: false=
is also how you give applications their three-finger swipes back.

*Cost.* One scene render per tag in the journey, once, at the start; the
two ends are stored at full resolution and the tags passed through at
half, since they are only ever seen turning and blurred. After that it is
a handful of textured quads a frame.

**** Overview (expo)
:PROPERTIES:
:CUSTOM_ID: expo
:END:

Every tag at once, as a grid of live thumbnails, with the camera pulling
back out of the one you are on. Opt in with =modules.expo.enabled: true=;
CMacs loads it by default.

Open it with a four-finger swipe up, or bind a key to the command:

#+begin_src yaml
keybinds:
  "Super+grave": { action: ipc_command, arg: "expo" }
#+end_src

Inside: arrows or =hjkl= move, =1= to =9= jump straight to a tag,
=Return= or a click picks, =Escape= leaves everything as it was. Clicking
the gap between tiles dismisses without changing tag.

| Property               | Type   | Default           | Description |
|------------------------+--------+-------------------+-------------|
| =expo=                 | bool   | =true=            | Master switch |
| =expo-duration=        | int    | =340=             | Milliseconds to zoom out, and back |
| =expo-curve=           | string | ="ease-out-expo"= | Zoom curve, from the shared curve set |
| =expo-tags=            | int    | =9=               | Tags shown, =1= to =9=; fewer means bigger tiles |
| =expo-columns=         | int    | =0=               | =0= picks a near-square grid |
| =expo-gap=             | float  | =0.06=            | Spacing between tiles, as a fraction of a tile |
| =expo-corner=          | float  | =0.035=           | Tile corner rounding, as a fraction of a tile |
| =expo-dim=             | float  | =0.45=            | How much dimmer an unselected tag is |
| =expo-hide-empty=      | bool   | =false=           | Drop tags with no windows from the grid |
| =expo-backdrop-color=  | string | ="#12141f"=       | Behind the grid; palette names resolve |

*The grid moves as one object.* Opening is a single transform applied to
every tile rather than nine tiles animating separately, so it reads as
the camera pulling back from one desktop instead of as pictures flying
into formation. At either end that transform is EXACT: the tile you came
from is precisely the screen, so the overview opens out of the live
desktop and closes back into the tag you picked with no cut.

*Every tile keeps the output's shape*, because every tile is a picture of
that output. The grid is therefore sized to whichever of width or height
runs out first and centred in the other, and a short last row is centred
under the rows above it.

*The tag being viewed is always in the grid*, even with =expo-hide-empty=
on and nothing on it --- the overview has to open out of somewhere, and
that somewhere is where you are.

**** Window switcher
:PROPERTIES:
:CUSTOM_ID: switcher
:END:

Alt-tab as a strip of live window previews, receding and turning away
from the middle. Opt in with =modules.switcher.enabled: true=; CMacs
loads it by default.

Hold =Super= or =Alt= and tap =Tab=; let go to commit. That fallback
binding only applies when your own config has not claimed the key ---
gowl offers a key to modules after its own keybind table has declined
it. To bind it explicitly, or to drive it from elsewhere:

#+begin_src yaml
keybinds:
  "Super+Tab":       { action: ipc_command, arg: "switcher-next" }
  "Super+Shift+Tab": { action: ipc_command, arg: "switcher-prev" }
#+end_src

| Property                   | Type   | Default           | Description |
|----------------------------+--------+-------------------+-------------|
| =switcher=                 | bool   | =true=            | Master switch |
| =switcher-duration=        | int    | =220=             | Milliseconds to slide from one card to the next |
| =switcher-curve=           | string | ="ease-out-expo"= | Reserved for the slide; the strip currently eases exponentially |
| =switcher-scale=           | float  | =0.52=            | Card width as a fraction of the output |
| =switcher-spacing=         | float  | =0.62=            | Distance between cards, as a fraction of a card |
| =switcher-angle=           | float  | =52=              | Degrees the off-centre cards turn away; =0= is a flat strip |
| =switcher-reflection=      | float  | =0.28=            | Reflection under the cards |
| =switcher-all-tags=        | bool   | =false=           | Also list windows on other tags |
| =switcher-backdrop-color=  | string | ="#0e1018"=       | Behind the strip |

*The order is the focus stack*, most recently focused first, and it opens
on the SECOND card. That is the entire reason alt-tab is worth having: one
tap lands on the window you were in before this one.

*Cards are pictures of windows, not of the desktop.* Each is captured
with everything else hidden --- the wallpaper included --- so three
terminals with the same icon are told apart by what is in them.

*Commands.* =switcher=, =switcher-next=, =switcher-prev=,
=switcher-close= (add =cancel= to leave focus alone),
=switcher-select N=, and =switcher-list=, which returns one
tab-separated =index/app-id/title= line per card. The last two are what
let an external picker drive the strip: CMacs uses them to make an
ordinary =completing-read= with the compositor's 3D preview underneath
it.

**** Magnifier
:PROPERTIES:
:CUSTOM_ID: magnifier
:END:

Hold the modifier and scroll to magnify the whole output around the
pointer. Opt in with =modules.magnifier.enabled: true=; CMacs loads it by
default. =Super+plus=, =Super+minus= and =Super+0= work as fallbacks when
your config has not bound them.

| Property                    | Type   | Default   | Description |
|-----------------------------+--------+-----------+-------------|
| =magnifier=                 | bool   | =true=    | Master switch |
| =magnifier-max=             | float  | =8.0=     | How far in it will go, =1.0= to =32.0= |
| =magnifier-step=            | float  | =1.25=    | Multiplier per wheel click |
| =magnifier-smoothing=       | int    | =120=     | Milliseconds for the zoom and pan to catch up; =0= is instant |
| =magnifier-follow-cursor=   | bool   | =true=    | Pan to keep the pointer in view |
| =magnifier-smooth=          | bool   | =true=    | =false= shows the actual pixels, unfiltered |
| =magnifier-modifier=        | string | ="Super"= | =Super=, =Alt=, =Ctrl= or =Shift= |

*A scroll the magnifier claims never reaches the client*, so
=magnifier-modifier= has to name a combination applications do not use.
An unrecognised name falls back to =Super= with a warning rather than to
"no modifier", which would make the mouse wheel stop working everywhere.

*It zooms towards the pointer*, not the middle of the screen: anchoring
on the centre sends whatever you are pointing at sliding off the edge as
you zoom in.

*It is the only effect that captures every frame*, because the thing it
is magnifying is live. At =1.0= it puts everything away --- the sheet,
the texture and the per-frame capture --- so an unzoomed session costs
nothing. It also sits above the bar, since a magnifier that magnified
everything except the panel would be useless to somebody who needs it to
read the panel.

**** Frosted glass and shadows
:PROPERTIES:
:CUSTOM_ID: blur
:END:

Blurred backdrops behind translucent windows, and soft drop shadows under
all of them. Opt in with =modules.blur.enabled: true=; CMacs loads it by
default. Windows become translucent through the =alpha= module or a
window rule; this module supplies what shows through them.

| Property            | Type   | Default     | Description |
|---------------------+--------+-------------+-------------|
| =blur=              | bool   | =true=      | Blur behind translucent windows |
| =blur-downscale=    | int    | =4=         | How much smaller the blur is computed, =1= to =8= |
| =blur-passes=       | int    | =3=         | Box passes, =1= to =6= |
| =blur-brightness=   | float  | =0.9=       | Applied to the blurred backdrop |
| =shadow=            | bool   | =true=      | Drop shadows |
| =shadow-radius=     | int    | =28=        | Softness in pixels; =0= disables shadows |
| =shadow-opacity=    | float  | =0.42=      | Peak opacity |
| =shadow-offset-x=   | int    | =0=         | Horizontal offset |
| =shadow-offset-y=   | int    | =10=        | Vertical offset |
| =shadow-color=      | string | ="#000000"= | Palette names resolve |

*What the blur actually blurs.* The WALLPAPER, computed once and cropped
per window. It does not blur other windows. Doing that honestly would
cost a full scene render per translucent window per frame --- three or
four extra renders at sixty hertz, for a look --- where this costs one
capture and one blur for as long as the wallpaper stays put. A
translucent terminal over the desktop is indistinguishable either way; a
translucent window over ANOTHER window shows blurred wallpaper rather
than a blurred copy of the window below. That is the trade, stated
plainly.

The blurred copy is rebuilt when the tag changes, so it follows
[[#wallpaper-tags][per-tag wallpapers]].

*Shadows are computed, not drawn and blurred.* A blurred rectangle has a
closed form, so a shadow costs one CPU pass when a window is resized and
nothing per frame --- a window being dragged changes position constantly
and size never, and the shadow is not redrawn for any of it.

Neither decoration claims any event: they follow the window rather than
placing it, so loading this module changes nothing about how windows
move.

**** Per-tag wallpaper
:PROPERTIES:
:CUSTOM_ID: wallpaper-tags
:END:

=wallpaper= keeps its meaning: the picture every tag uses. =wallpaper-tags=
overrides it for individual tags, and a tag with no entry keeps the
default --- so this is purely additive to an existing config.

#+begin_src yaml
wallpaper: "~/Pictures/default.jpg"
wallpaper-fade: 320
wallpaper-tags:
  1: "~/Pictures/code.jpg"
  4: "~/Pictures/mail.png"
#+end_src

| Property           | Type | Default | Description |
|--------------------+------+---------+-------------|
| =wallpaper-tags=   | map  | empty   | Tag number (1-9) to image path |
| =wallpaper-fade=   | int  | =320=   | Milliseconds to cross-fade; =0= cuts |

Keys are the tag numbers shown in the bar, so 1-based. A key outside 1-9
is a typo and is reported and skipped rather than landing on tag 1.

A combined tag view uses its LOWEST tag to choose, the same rule the cube
uses to choose a face: adding a tag to a view does not change the
wallpaper, and replacing one does.

The cross-fade stacks the incoming picture above the outgoing one and
fades it up, rather than swapping a buffer --- a swap is a cut, and the
setting exists precisely so that it is not one. Every wallpaper the
config mentions is decoded once and kept, so switching back to a tag does
not re-read its file.

**** tags
:PROPERTIES:
:CUSTOM_ID: tags
:END:
Tag (workspace) settings.

| Property | Type | Default | Description             |
|----------+------+---------+-------------------------|
| =count=  | int  | =9=     | Number of tags (1 - 31) |

*** Keybinds
:PROPERTIES:
:CUSTOM_ID: keybinds
:END:
Keybinds are defined in the =keybinds= section as a mapping of key strings to action objects.

**** Key String Format
:PROPERTIES:
:CUSTOM_ID: key-string-format
:END:
#+begin_example
Modifier+Modifier+Key
#+end_example

Modifier names (case-insensitive):

- =Super= or =Logo= -- Super/Windows key
- =Shift= -- Shift key
- =Ctrl= or =Control= -- Control key
- =Alt= or =Mod1= -- Alt key
- =Mod2= -- Num Lock (typically)
- =Mod3= -- Mod3
- =Mod5= -- Mod5

The last token in the =+=-separated string is the key name, resolved via =xkb_keysym_from_name()=. Common examples: =Return=, =space=, =Tab=, =a=-=z=, =0=-=9=, =F1=-=F12=, =comma=, =period=, =bracketleft=, =bracketright=.

A bind does not need a modifier. The =XF86*= keysyms that laptop media keys emit --- =XF86AudioRaiseVolume=, =XF86AudioMute=, =XF86MonBrightnessUp=, =XF86AudioPlay= and friends --- resolve through the same call as every other key name, and dispatch compares the cleaned modifier mask, so a mask of zero matches like any other combination. The shipped =default-config.yaml= binds ten of them.

**** Action Object Format
:PROPERTIES:
:CUSTOM_ID: action-object-format
:END:
#+begin_src yaml
"Super+Return": { action: spawn, arg: "gst", desc: "Terminal" }
#+end_src

| Field    | Type   | Required | Description                                   |
|----------+--------+----------+-----------------------------------------------|
| =action= | string | yes      | The action to perform (see action list below) |
| =arg=    | string | no       | Argument for the action                       |
| =desc=   | string | no       | Human-readable description of the bind        |

=desc= never affects dispatch. It exists so that something can render what a bind /does/ rather than the action name it happens to use: the MCP =list_keybinds= tool returns it, and under cmacs =cmacs-gowl-describe-keybinds= builds a cheatsheet from it. A bind with no =desc= still lists, falling back to its action and argument.

**** Actions
:PROPERTIES:
:CUSTOM_ID: actions
:END:
| Action              | Argument                         | Description                                 |
|---------------------+----------------------------------+---------------------------------------------|
| =spawn=             | command string                   | Spawn an external process                   |
| =kill_client=       | --                               | Close the focused client                    |
| =toggle_float=      | --                               | Toggle floating state on focused client     |
| =toggle_fullscreen= | --                               | Toggle fullscreen on focused client         |
| =focus_stack=       | ="+1"= or ="-1"=                 | Move focus forward or backward in the stack |
| =focus_monitor=     | ="+1"= or ="-1"=                 | Move focus to next or previous monitor      |

| =tag_toggle=        | ="1"= - ="9"=                    | Toggle a tag on the focused client          |
| =move_to_monitor=   | ="+1"= or ="-1"=                 | Move focused client to next/prev monitor    |

**** The =custom= action
:PROPERTIES:
:CUSTOM_ID: custom-action
:END:
=custom= is the escape hatch from the fixed action list. The compositor does not interpret its =arg= at all; it hands the string to whatever embedder registered a handler with =gowl_compositor_set_custom_action_handler()=, and consumes the key either way.

Standalone gowl registers no handler, so a =custom= bind is inert here --- it is logged at debug level and swallowed. It exists for embedders. Under =emacs --gowl= the handler evaluates the =arg= as an Elisp form, which is what lets a compositor key run editor code rather than being limited to the actions above or to spawning a subprocess:

#+begin_src yaml
"XF86AudioRaiseVolume": { action: custom, arg: "(cmacs-volume-raise)" }
#+end_src

**** Example
:PROPERTIES:
:CUSTOM_ID: example
:END:
#+begin_src yaml
keybinds:
  "Super+Return": { action: spawn, arg: "gst", desc: "Terminal" }
  "Super+p": { action: spawn, arg: "wofi --show drun", desc: "App launcher" }
  "Super+Shift+p": { action: spawn, arg: "wofi --show run", desc: "Run command" }
  "Super+Shift+c": { action: kill_client, desc: "Close window" }
  "Super+j": { action: focus_stack, arg: "+1", desc: "Focus next window" }
  "Super+k": { action: focus_stack, arg: "-1", desc: "Focus previous window" }
  "Super+h": { action: set_mfact, arg: "-0.05", desc: "Shrink master area" }
  "Super+l": { action: set_mfact, arg: "+0.05", desc: "Grow master area" }
  "Super+v": { action: set_split, arg: "vsplit", desc: "Vertical split" }
  "Super+Shift+v": { action: set_split, arg: "normal", desc: "Horizontal split" }
  "Super+1": { action: tag_view, arg: "1" }
  "Super+Shift+1": { action: tag_set, arg: "1" }
  "Super+Shift+q": { action: quit, desc: "Quit gowl" }

  # Media keys need no modifier.
  "XF86AudioRaiseVolume":
    { action: spawn, desc: "Volume up",
      arg: "wpctl set-volume -l 1.0 @DEFAULT_AUDIO_SINK@ 5%+" }
  "XF86AudioMute":
    { action: spawn, desc: "Mute output",
      arg: "wpctl set-mute @DEFAULT_AUDIO_SINK@ toggle" }
  "XF86MonBrightnessUp":

  "XF86AudioPlay":

The shipped media binds use =wpctl= (from wireplumber, present wherever pipewire is), =brightnessctl= and =playerctl=. The latter two are separate packages; a bind whose command is not installed simply fails to spawn.

*** Window Rules
:PROPERTIES:
:CUSTOM_ID: window-rules
:END:
Rules match clients by =app_id= and/or =title= and apply settings.

| Field      | Type   | Default | Description                                 |
|------------+--------+---------+---------------------------------------------|
| =app_id=   | string | =""=    | Wayland app_id to match (empty = match any) |
| =title=    | string | =""=    | Window title pattern (empty = match any)    |
| =tags=     | int    | =0=     | Tag bitmask to assign (0 = no override)     |
| =floating= | bool   | =false= | Whether the client should float             |
| =monitor=  | int    | =-1=    | Monitor index (-1 = default)                |

**** Example
:PROPERTIES:
:CUSTOM_ID: example-1
:END:
#+begin_src yaml
rules:
  - app_id: "firefox"
    tags: 2
    floating: false
    monitor: -1

  - app_id: "pavucontrol"
    floating: true

  - app_id: "mpv"
    floating: true
    tags: 0
    monitor: -1
#+end_src

**** =rules.d/=
:PROPERTIES:
:CUSTOM_ID: rules-d
:END:

Rules may also live one file per application in a =rules.d/= directory
beside the config file --- =~/.config/gowl/rules.d/10-steam.yaml=,
=20-picture-in-picture.yaml=, and so on.  Each is an ordinary config
fragment carrying its own =rules:= sequence, so it is a valid config
file in its own right.

Files load in sorted order after the main config's flat =rules:= list,
so a numeric prefix decides precedence and the two mechanisms merge
rather than competing.

#+begin_src yaml
# ~/.config/gowl/rules.d/10-steam.yaml
rules:
  - app-id: "steam"
    floating: true
    tags: 16
#+end_src

A fragment that does not parse costs itself and nothing else: it warns,
is skipped, and every rule that did parse stays.  These are files
edited by hand, and one typo should not take out the rest or stop the
compositor starting.

Why this exists at all: a single growing =rules:= array is the wrong
shape for the job.  A rule for Steam and a rule for a screenshot
overlay have nothing to do with each other, and a distribution that
ships rules cannot be edited by a user without merging.  Omarchy keeps
one Lua file per application for the same reason.

*** Monitor Configuration
:PROPERTIES:
:CUSTOM_ID: monitor-configuration
:END:
Per-output settings keyed by output name. Each field is independently
optional --- set only what you need to override; unset fields stay at the
compositor's defaults. Output names come from the kernel / DRM (e.g.
=eDP-1=, =HDMI-A-1=, =DP-2=, =WL-1=, =headless-1=) --- discover them via
=cmacsgi monitor list= or =M-: (cmacs-gowl-list-monitors)=.

#+begin_src yaml
monitors:
  eDP-1:
    transform: 90        # mobile screen: boot already-rotated
  HDMI-A-1:
    width: 2560
    height: 1440
    refresh: 144.0
    x: 1920
    y: 0
    scale: 1.0
    enabled: true
#+end_src

| Field       | Type              | Meaning                                                                  |
|-------------+-------------------+--------------------------------------------------------------------------|
| =width=     | int               | Preferred mode width in pixels (must pair with =height=).                |
| =height=    | int               | Preferred mode height in pixels.                                         |
| =refresh=   | float             | Refresh rate in Hz (e.g. =60.0=). Omit / =0= for the output's preferred. |
| =x=         | int               | Layout X coordinate.                                                     |
| =y=         | int               | Layout Y coordinate.                                                     |
| =scale=     | float             | HiDPI scale factor (e.g. =1.0=, =1.5=, =2.0=).                           |
| =enabled=   | bool              | =true= to power on, =false= to disable.                                  |
| =transform= | int 0--7 / string | =wl_output_transform= code, or one of the canonical names below.         |

**** =transform= values
:PROPERTIES:
:CUSTOM_ID: transform-values
:END:
| Code | Name          | Effect               |
|------+---------------+----------------------|
| 0    | =normal=      | No rotation          |
| 1    | =90=          | Rotate 90° CCW       |
| 2    | =180=         | Upside down          |
| 3    | =270=         | Rotate 90° CW        |
| 4    | =flipped=     | Horizontal mirror    |
| 5    | =flipped-90=  | Mirror + rotate 90°  |
| 6    | =flipped-180= | Mirror + rotate 180° |
| 7    | =flipped-270= | Mirror + rotate 270° |

Changes take effect live on =M-x cmacs-gowl-reload-config=, the
equivalent =cmacsgi compositor reload=, and the =Mod+R= keybind --- no
compositor restart required.

*** Module Configuration
:PROPERTIES:
:CUSTOM_ID: module-configuration
:END:
Per-module settings passed to the module's =configure()= method:

#+begin_src yaml
modules:
  vanitygaps:
    enabled: true
    inner-gap: 5
    outer-gap: 10
  pertag:
    enabled: true
  autostart:
    enabled: true
  wallpaper:
    enabled: true
    path: "~/Pictures/wallpaper.png"
    # Scaling mode: fill | fit | center | stretch | tile
    mode: fill
#+end_src

The wallpaper =mode= controls how the image is mapped onto each
monitor.  The default =fill= is GNOME-style "zoom": the image is scaled
(up or down) to fully cover the monitor while preserving its aspect
ratio and is centre-cropped — it is never stretched, and never tiled
into a grid.  =fit= letterboxes the whole image inside the monitor,
=center= places it 1:1, =stretch= distorts it to the exact monitor
size, and =tile= repeats it at native size.  Each monitor is scaled
independently, so a large panoramic image is correctly zoomed to fit
each display rather than tiled.

** C Configuration
:PROPERTIES:
:CUSTOM_ID: c-configuration
:END:
*** Overview
:PROPERTIES:
:CUSTOM_ID: overview-1
:END:
The C config system allows full programmatic control of the compositor using the gowl C API. The config source is a standard C file that gets compiled to a shared object (=.so=) at startup by =GowlConfigCompiler=.

*** Search Paths
:PROPERTIES:
:CUSTOM_ID: search-paths-1
:END:
The compositor searches for =config.c= in:

1. =~/.config/gowl/config.c= (user config)
2. =/etc/gowl/config.c= (system-wide config)

Override with =--c-config=:

#+begin_src sh
gowl --c-config /path/to/config.c
#+end_src

Disable C config entirely:

#+begin_src sh
gowl --no-c-config
#+end_src

*** Generating a Default C Config
:PROPERTIES:
:CUSTOM_ID: generating-a-default-c-config
:END:
#+begin_src sh
gowl --generate-c-config > ~/.config/gowl/config.c
#+end_src

*** How It Works
:PROPERTIES:
:CUSTOM_ID: how-it-works
:END:
1. The compositor finds =config.c= in the search paths.
2. =GowlConfigCompiler= reads the file and scans for an optional =#define CRISPY_PARAMS= to extract extra compiler flags.
3. The file is compiled via the crispy library with SHA256 content-hash caching.
4. The compiled =.so= is cached in =$XDG_CACHE_HOME/gowl/= (filename derived from content hash).
5. The =.so= is opened via =g_module_open()= and the =gowl_config_init= symbol is resolved and called.
6. After the compositor is fully started, the optional =gowl_config_ready= symbol is looked up and called (if present).
7. If compilation fails, the compositor logs a warning and continues with YAML/default config.

*** CRISPY_PARAMS
:PROPERTIES:
:CUSTOM_ID: crispy_params
:END:
Optional define to pass extra compiler flags. Shell expansion is supported:

#+begin_src C
#define CRISPY_PARAMS ""
#+end_src

This is useful for specifying additional include paths or libraries:

#+begin_src C
#define CRISPY_PARAMS "-I/opt/custom/include -lm"
#+end_src

Shell expansion example (runs at compile time):

#+begin_src C
#define CRISPY_PARAMS "$(pkg-config --cflags json-glib-1.0)"
#+end_src

If omitted, only the default pkg-config flags are used.

*** gowl_config_init Entry Point
:PROPERTIES:
:CUSTOM_ID: gowl_config_init-entry-point
:END:
The =.so= must export a single function:

#+begin_src C
G_MODULE_EXPORT gboolean
gowl_config_init(void)
{
    /* configuration code here */
    return TRUE;
}
#+end_src

This function has access to two extern symbols provided by the compositor:

#+begin_src C
extern GowlCompositor *gowl_compositor;
extern GowlConfig     *gowl_config;
#+end_src

**** Setting Properties
:PROPERTIES:
:CUSTOM_ID: setting-properties
:END:
Use =g_object_set()= on =gowl_config=:

#+begin_src C
g_object_set(gowl_config,
    "border-width", 3,
    "mfact", 0.60,
    "terminal", "kitty",
    NULL);
#+end_src

**** Adding Keybinds
:PROPERTIES:
:CUSTOM_ID: adding-keybinds
:END:
Use =gowl_config_add_keybind()=, or =gowl_config_add_keybind_full()= when the bind should carry a description:

#+begin_src C
#include <xkbcommon/xkbcommon.h>

gowl_config_add_keybind(gowl_config,
    GOWL_KEY_MOD_LOGO, XKB_KEY_Return,
    GOWL_ACTION_SPAWN, "gst");

gowl_config_add_keybind(gowl_config,
    GOWL_KEY_MOD_LOGO | GOWL_KEY_MOD_SHIFT, XKB_KEY_c,
    GOWL_ACTION_KILL_CLIENT, NULL);

/* Same thing, with a description for the cheatsheet. */
gowl_config_add_keybind_full(gowl_config,
    GOWL_KEY_MOD_LOGO, XKB_KEY_Return,
    GOWL_ACTION_SPAWN, "gst", "Terminal");
#+end_src

=gowl_config_add_keybind()= is a wrapper that passes a =NULL= description, so existing C configs need no change.

**** Adding Rules
:PROPERTIES:
:CUSTOM_ID: adding-rules
:END:
Use =gowl_config_add_rule()=:

#+begin_src C
gowl_config_add_rule(gowl_config,
    "firefox", NULL,    /* app_id, title */

*** Return Value
:PROPERTIES:
:CUSTOM_ID: return-value
:END:
Return =TRUE= on success. Return =FALSE= to signal failure; the compositor will log a warning and fall back to the YAML/default configuration.

*** gowl_config_ready Entry Point (Optional)
:PROPERTIES:
:CUSTOM_ID: gowl_config_ready-entry-point-optional
:END:
The =.so= may optionally export a second function:

#+begin_src C
G_MODULE_EXPORT void
gowl_config_ready(void)
{
    /* called after compositor is fully started */
}
#+end_src

This function is called *once* after the compositor is fully started and the Wayland display is ready to accept clients. It has access to the same extern symbols (=gowl_compositor=, =gowl_config=) as =gowl_config_init=.

Use =gowl_config_ready= to spawn Wayland clients that need a running compositor --- status bars, notification daemons, wallpaper setters, etc. These cannot be spawned from =gowl_config_init= because the Wayland display does not exist yet at that point.

If the symbol is absent, the compositor silently skips the call.

**** Example: Spawning a Status Bar
:PROPERTIES:
:CUSTOM_ID: example-spawning-a-status-bar
:END:
#+begin_src C
static void
spawn_gowlbar(void)
{
    g_autofree gchar *path = NULL;
    gchar            *argv[] = { NULL, NULL };
    GError           *error  = NULL;

    path = g_find_program_in_path("gowlbar");
    if (path == NULL)
        return;

    argv[0] = path;
    if (!g_spawn_async(NULL, argv, NULL, G_SPAWN_DEFAULT,
                       NULL, NULL, NULL, &error)) {
        g_printerr("failed to spawn gowlbar: %s\n", error->message);
        g_clear_error(&error);
    }
}

G_MODULE_EXPORT void
gowl_config_ready(void)
{
    spawn_gowlbar();
}
#+end_src

** Using Both YAML and C Config
:PROPERTIES:
:CUSTOM_ID: using-both-yaml-and-c-config
:END:
When both configs are present:

1. Built-in defaults are applied.
2. YAML config is loaded (overrides defaults).
3. C config runs (overrides YAML).

A common pattern is to use YAML for declarative settings and C config only for things that require logic (conditional keybinds, computed values, etc.):

#+begin_src yaml
# config.yaml -- base settings
appearance:
  border-width: 2
  border-color-focus: accent

layout:
  mfact: 0.55
#+end_src

#+begin_src C
/* config.c -- conditional overrides */
G_MODULE_EXPORT gboolean
gowl_config_init(void)
{
    const gchar *hostname;

    hostname = g_get_host_name();

    /* Different mfact on ultrawide monitor setup */
    if (g_str_equal(hostname, "workstation")) {
        g_object_set(gowl_config, "mfact", 0.35, NULL);
    }

    return TRUE;
}
#+end_src
