* MCP Server Module
:PROPERTIES:
:CUSTOM_ID: mcp-server-module
:END:
The MCP (Model Context Protocol) module exposes compositor state and controls to AI assistants like Claude Code. It implements the MCP protocol using [[https://gitlab.com/copyleftgames/mcp-glib][mcp-glib]], enabling AI tools to query windows, manage tags, adjust layouts, and more.

** Quick Start
:PROPERTIES:
:CUSTOM_ID: quick-start
:END:
1. Enable the module in your config (=~/.config/gowl/config.yaml=):

#+begin_src yaml
modules:
  mcp:
    enabled: true
#+end_src

2. [@2] Configure Claude Code to use the =gowl-mcp= relay binary. Add to your Claude Code MCP settings:

#+begin_src json
{
  "mcpServers": {
    "gowl": {
      "command": "/usr/local/bin/gowl-mcp"
    }
  }
}
#+end_src

3. [@3] Restart gowl. The MCP module starts a Unix socket at =$XDG_RUNTIME_DIR/gowl-mcp.sock=.

*** Threading Model
:PROPERTIES:
:CUSTOM_ID: threading-model
:END:
The compositor runs on the Wayland event loop. The MCP module spawns a dedicated =GThread= with its own =GMainLoop= for MCP server I/O. Tool calls are dispatched to the compositor thread via =eventfd= + mutex/cond signaling, ensuring all compositor state access is thread-safe.

** Transports
:PROPERTIES:
:CUSTOM_ID: transports
:END:
*** Unix Socket (stdio relay) -- Default
:PROPERTIES:
:CUSTOM_ID: unix-socket-stdio-relay----default
:END:
The module creates a listening Unix socket at =$XDG_RUNTIME_DIR/gowl-mcp.sock=. The =gowl-mcp= binary bridges stdin/stdout to this socket using NDJSON framing, which is what MCP clients like Claude Code expect.

Override the socket path:

- Environment variable: =GOWL_MCP_SOCKET=/path/to/socket gowl-mcp=
- CLI flag: =gowl-mcp --socket /path/to/socket=

*** HTTP+SSE
:PROPERTIES:
:CUSTOM_ID: httpsse
:END:
Direct HTTP connections with Server-Sent Events. Enable with:

#+begin_src yaml
modules:
  mcp:
    enabled: true
    transport-http: true
    http-host: "127.0.0.1"
    http-port: 8716
    # http-auth-token: "secret"
#+end_src

When =http-auth-token= is set, clients must include =Authorization: Bearer <token>= in requests.

** Configuration
:PROPERTIES:
:CUSTOM_ID: configuration
:END:
All settings go under =modules: mcp:= in your YAML config.

| Key               | Type   | Default     | Description                               |
|-------------------+--------+-------------+-------------------------------------------|
| =enabled=         | bool   | =false=     | Enable the MCP module                     |
| =transport-stdio= | bool   | =true=      | Enable Unix socket for stdio relay        |
| =transport-http=  | bool   | =false=     | Enable HTTP+SSE transport                 |
| =http-host=       | string | =127.0.0.1= | HTTP bind address                         |
| =http-port=       | int    | =8716=      | HTTP listen port                          |
| =http-auth-token= | string | (empty)     | Bearer token for HTTP auth                |
| =instructions=    | string | (built-in)  | Custom instructions for AI clients        |
| =tools=           | string | (all)       | Newline-delimited allowlist of tool names |

*** Tool Allowlist
:PROPERTIES:
:CUSTOM_ID: tool-allowlist
:END:
By default, all tools are enabled. To restrict available tools, set the =tools= key to a newline-delimited list:

#+begin_src yaml
modules:
  mcp:
    enabled: true
    tools: |
      list_clients
      list_monitors
      describe_desktop
      find_window
      get_focused_client
#+end_src

Only listed tools will be registered. Omit the =tools= key entirely to enable all tools.

*** Per-Device Input Remapping
:PROPERTIES:
:CUSTOM_ID: input-remap-tools-mcp
:END:
Thin wrappers over the opt-in =inputremap= module's IPC words ([[file:input-remap.org][input-remap.org]]).  Each reports plainly when the module is not loaded.

| Tool                          | Parameters                     | Description                                              |
|-------------------------------+--------------------------------+----------------------------------------------------------|
| =input_remap_list_devices=    | --                             | Every keyboard and pointer: id, type, name, vendor-product, sysname, claimed |
| =input_remap_list=            | --                             | The rules in force, their source, YAML and matched devices |
| =input_remap_status=          | --                             | Enabled, rule and claim counts, log level, identify state |
| =input_remap_add=             | =rule= (object) or =yaml= (one line) | Add or replace a rule; sequences are refused (a ={macro:}= target is allowed) |
| =input_remap_remove=          | =name=                         | Remove a rule; released devices rejoin the keyboard       |
| =input_remap_identify=        | =seconds= (optional)           | Listen for the next press on any device, consuming nothing |
| =input_remap_identify_result= | --                             | The device and input caught, =pending= or =none=          |

A =rule= object is the same schema as a YAML rule --- JSON is YAML flow syntax, so it goes to the same parser:

#+begin_src json
{"rule": {"name": "wow-pedals",
          "match": {"id": "1a86:e026", "type": "keyboard"},
          "map": {"KEY_A": {"button": "middle"},
                  "KEY_B": {"action": "focus-client", "arg": "title:World of Warcraft*"}}}}
#+end_src

*** Macros
:PROPERTIES:
:CUSTOM_ID: macro-tools-mcp
:END:
Thin wrappers over the opt-in =macro= module's IPC words ([[file:macros.org][macros.org]]).  Each reports plainly when the module is not loaded.

| Tool           | Parameters                        | Description                                              |
|----------------+-----------------------------------+----------------------------------------------------------|
| =macro_run=    | =name=, =args= (array, optional)  | Run a macro by name or path (trigger =api=)              |
| =macro_stop=   | =which= (name, id or =all=)       | Stop running macros                                      |
| =macro_list=   | --                                | Every macro runnable by name, with held-back state       |
| =macro_status= | --                                | Running runs, held-back macros and why, fault count     |
| =macro_info=   | =name=                            | Path, description, mode, time budget                     |
| =macro_clear=  | =name= (optional)                 | Let a held-back macro run again                          |
| =macro_triggers= | --                              | Triggers, their filters as understood, fired/skipped     |
| =macro_filter_test= | =filter=, =event= (optional) | Judge a filter now, with every field's value             |
| =macro_record= | =action= (=start=, =stop=, =cancel=, =status=), =name= (optional) | The macro recorder; =stop= writes =last-recording.c= (and =NAME.c=) and replies =recorded NAME STEPS PATH= |
| =macro_voice_match= | =text=, =dry_run= (boolean, optional) | Run the macro a sentence names, as Super+Alt+m does; dry, only say what it would run |
| =macro_voice_status= | -- | The listener: listening, command, limit, last heard, last error |

*=macro_record start= needs consent.*  The Super+Alt+r key needs none ---
the person pressed it --- but a program asking to watch the person's
input is the case the input recorder's =input-recording= key exists
for, so this tool passes =--require-consent= and is refused while that
key is off (the default).  Everything else about the recording is the
key's: the frame round the screen, no capture in password prompts or on
the lock screen, Super+Shift+Escape, the deadline.

*There is no tool that turns the microphone on.*  =macro_voice_match= is
the half an agent has a use for: it matches a sentence to a macro the
way the voice key does --- a configured phrase, a macro's name said as
words (="pip corner 25"= runs =pip-corner 25=), every word of a name ---
and runs it with trigger =voice=.  =dry_run= returns what was heard, the
normalised form, and the macro and arguments, and runs nothing.

*** Input Recording
:PROPERTIES:
:CUSTOM_ID: input-recording-tools-mcp
:END:
The mirror image of the tools above: observing real input rather than
injecting synthetic input.  A separate tool category on purpose, so a
=tools:= allowlist can grant injection without granting capture -- and
gated again by the compositor's own =input-recording= config key,
which is *off by default*.  An allowlist entry alone cannot turn
recording on.

| Tool               | Parameters                    | Description                                        |
|--------------------+-------------------------------+----------------------------------------------------|
| =start_recording=  | =max_seconds?=, =max_events?= | Begin a bounded recording; returns a token         |
| =drain_recording=  | =token=                       | Take what is buffered, keep recording              |
| =stop_recording=   | =token=                       | Stop and take the tail                             |
| =recording_status= | (none)                        | State and counters, consuming nothing              |

While a recording runs the whole screen is framed in red, and
=Super+Shift+Escape= stops it without needing the token.  Capture is
suppressed while the session is locked and while the focused window
matches the deny list, but *gowl cannot see a password field inside an
ordinary window* -- read [[file:input-recording.org][Input Recording]] before enabling this.

*** Screenshot
:PROPERTIES:
:CUSTOM_ID: screenshot
:END:
| Tool                 | Parameters                                        | Description                                     |
|----------------------+---------------------------------------------------+-------------------------------------------------|
| =screenshot_client=  | =id=                                              | Capture a client window (returns base64 PNG)    |
| =screenshot_monitor= | =monitor= (optional)                              | Capture entire output (returns base64 PNG)      |
| =screenshot_region=  | =x=, =y=, =width=, =height=, =monitor= (optional) | Capture rectangular region (returns base64 PNG) |

Screenshots are returned as base64-encoded PNG images via the MCP image content type.

=screenshot_region= takes its rectangle in *layout* coordinates --- the same ones =gowl_list_monitors= reports and a client's geometry is in --- not in the output's raw pixels. On a scaled monitor the image that comes back is correspondingly larger than the rectangle asked for: a 400x300 region at =scale: 2= is an 800x600 PNG. See [[file:modules.org::*Layout coordinates and device pixels][Layout coordinates and device pixels]].

*** Text and Colours off the Screen
:PROPERTIES:
:CUSTOM_ID: grab-tools-mcp
:END:
The non-interactive halves of Super+Alt+Shift+s and Super+Alt+c: an
agent names the place instead of dragging or clicking.

| Tool          | Parameters                                                        | Description                                         |
|---------------+-------------------------------------------------------------------+-----------------------------------------------------|
| =screen_text= | =x=, =y=, =width=, =height=, =language= (optional), =copy= (boolean, optional) | The text in a region (OCR); =""= when there is none |
| =pick_color=  | =x=, =y=                                                          | ={"color":"#rrggbb","r":..,"g":..,"b":..}=          |

Layout coordinates, as =screenshot_region=.  *Neither touches the
clipboard* unless =copy= is true: a program reading the screen should
not replace what the person copied.

=screen_text= runs the screenshot module's own =ocr-command= and
=ocr-language= (asked for with =screenshot-ocr-config=; =tesseract= and
=eng= without the module), so the tool and the key run the same
program.  The capture happens on the compositor thread and is quick;
tesseract runs on the MCP thread, where a second costs nothing --- on the
compositor thread it would freeze the desktop.  The region is a 0600
PNG in =$XDG_RUNTIME_DIR=, deleted afterwards.  Needs =tesseract= and a
language pack (Fedora: =tesseract=, =tesseract-langpack-eng=).

*** Clipboard History
:PROPERTIES:
:CUSTOM_ID: clipboard-tools-mcp
:END:
Over the clipboard module's store.  These were written long ago and
left out of the registration list, so no client ever saw them; they are
registered now and tested end to end.

| Tool                     | Parameters | Description                                                 |
|--------------------------+------------+-------------------------------------------------------------|
| =list_clipboard=         | --         | The history, newest first: =ID TAB MIME TAB BYTES TAB PREVIEW= |
| =get_clipboard_entry=    | =id=       | The path of one entry's stored bytes                        |
| =copy_clipboard_entry=   | =id=       | Put an entry back on the clipboard                          |
| =delete_clipboard_entry= | =id=       | Forget one entry                                            |
| =clear_clipboard=        | --         | Forget them all                                             |

The history is everything the person copied, passwords included --- the
Super+space menu keeps it out of search for that reason.  The read and
write tools are separate allowlist entries, so a =tools:= list can grant
reading without granting =copy_clipboard_entry=.  What gowl puts on the
clipboard itself (OCR text, a colour, a screenshot, cmacs's kills) is in
the history too.

** gowl-mcp Relay Binary
:PROPERTIES:
:CUSTOM_ID: gowl-mcp-relay-binary
:END:
The =gowl-mcp= binary is a small stdio-to-socket relay. It connects to the module's Unix domain socket and bridges NDJSON lines between stdin/stdout and the socket.

#+begin_example
Usage: gowl-mcp [--socket PATH]

Options:
  --socket PATH   Unix socket path (default: $XDG_RUNTIME_DIR/gowl-mcp.sock)
  -h, --help      Show help
  --license       Show license

Environment:
  GOWL_MCP_SOCKET  Override socket path
#+end_example

** Build Requirements
:PROPERTIES:
:CUSTOM_ID: build-requirements
:END:
The MCP module is opt-in and requires =MCP=1= on the make command line:

#+begin_src sh
# Install MCP dependencies
make MCP=1 install-deps

# Build with MCP support
make MCP=1
make MCP=1 DEBUG=1    # debug build
#+end_src

The additional dependencies beyond the base compositor are:

#+begin_src sh
sudo dnf install libsoup3-devel libdex-devel libpng-devel
#+end_src

When =MCP=1= is set and the dependencies are found, the build produces:

- =mcp.so= -- the compositor module (in =build/<type>/modules/=)
- =gowl-mcp= -- the stdio relay binary (in =build/<type>/=)
