** Overview
:PROPERTIES:
:CUSTOM_ID: overview
:END:
Gowl modules are shared object (=.so=) plugins loaded at runtime via GModule (=g_module_open()=). Each module is a GObject subclass of =GowlModule= that implements one or more gowl interfaces to hook into compositor events.

** Module Architecture
:PROPERTIES:
:CUSTOM_ID: module-architecture
:END:
*** Base Class: GowlModule
:PROPERTIES:
:CUSTOM_ID: base-class-gowlmodule
:END:
Every module subclasses =GowlModule=, which is declared as a derivable type:

#+begin_src C
G_DECLARE_DERIVABLE_TYPE(GowlModule, gowl_module, GOWL, MODULE, GObject)
#+end_src

The class structure provides virtual methods:

| Virtual Method    | Signature                          | Description                                                  |
|-------------------+------------------------------------+--------------------------------------------------------------|
| =activate=        | =gboolean (*)(GowlModule *)=       | Called when the module is activated. Return TRUE on success. |
| =deactivate=      | =void (*)(GowlModule *)=           | Called when the module is deactivated.                       |
| =get_name=        | =const gchar *(*)(GowlModule *)=   | Return the human-readable module name.                       |
| =get_description= | =const gchar *(*)(GowlModule *)=   | Return a short description.                                  |
| =get_version=     | =const gchar *(*)(GowlModule *)=   | Return the version string.                                   |
| =configure=       | =void (*)(GowlModule *, gpointer)= | Apply configuration data.                                    |

*** Properties
:PROPERTIES:
:CUSTOM_ID: properties
:END:
=GowlModule= provides these GObject properties:

| Property    | Type | Default | Description                                        |
|-------------+------+---------+----------------------------------------------------|
| =priority=  | int  | 100     | Dispatch priority (lower = dispatched first)       |
| =is-active= | bool | FALSE   | Whether the module is currently active (read-only) |

*** Entry Point
:PROPERTIES:
:CUSTOM_ID: entry-point
:END:
Every =.so= module must export exactly one function:

#+begin_src C
G_MODULE_EXPORT GType
gowl_module_register(void)
{
    return MY_TYPE_MODULE;
}
#+end_src

This function returns the GType of the module's =GowlModule= subclass. The =GowlModuleManager= calls this to discover the module type, then instantiates it with =g_object_new()=.

** Creating a Module: Step by Step
:PROPERTIES:
:CUSTOM_ID: creating-a-module-step-by-step
:END:
*** 1. Define the Module Type
:PROPERTIES:
:CUSTOM_ID: 1-define-the-module-type
:END:
#+begin_src C
/*
 * my-module.c - Example Gowl Module
 *
 * Compile: gcc $(pkg-config --cflags --libs glib-2.0 gobject-2.0 gmodule-2.0 gowl)
 *          -shared -fPIC -o my-module.so my-module.c
 */

#include <gowl/gowl.h>

/* --- Type declaration --- */

#define MY_TYPE_MODULE (my_module_get_type())

G_DECLARE_FINAL_TYPE(MyModule, my_module, MY, MODULE, GowlModule)

struct _MyModule {
    GowlModule parent_instance;

    /* module-specific state */
    gint example_value;
};

/* Implement GowlStartupHandler interface */
static void
my_module_on_startup(
    GowlStartupHandler *handler,
    gpointer            compositor
){
    MyModule *self;

    self = MY_MODULE(handler);

    g_message("MyModule startup! example_value=%d", self->example_value);
}

static void
my_module_startup_handler_init(GowlStartupHandlerInterface *iface)
{
    iface->on_startup = my_module_on_startup;
}

/* Implement GowlKeybindHandler interface */
static gboolean
my_module_handle_key(
    GowlKeybindHandler *handler,
    guint               modifiers,
    guint               keysym,
    gboolean            pressed
){
    /* Example: intercept a specific keybind */
    if (pressed &&
        (modifiers & GOWL_KEY_MOD_LOGO) &&
        keysym == XKB_KEY_F12) {
        g_message("MyModule: F12 pressed!");
        return TRUE; /* consumed */
    }

    return FALSE; /* pass to next handler */
}

static void
my_module_keybind_handler_init(GowlKeybindHandlerInterface *iface)
{
    iface->handle_key = my_module_handle_key;
}
#+end_src

*** 2. Register Interfaces and Define the GType
:PROPERTIES:
:CUSTOM_ID: 2-register-interfaces-and-define-the-gtype
:END:

/* Register the type with both interfaces */

*** Using the Build System
:PROPERTIES:
:CUSTOM_ID: using-the-build-system
:END:
Place your module source in =modules/my-module/=:

#+begin_example
modules/
  my-module/
    Makefile
    my-module.c
#+end_example

The top-level =make modules= target will build all modules under =modules/=. Each module directory should have a =Makefile= that accepts =OUTDIR=, =LIBDIR=, =CFLAGS=, and =LDFLAGS= variables.

A minimal module =Makefile=:

#+begin_src makefile
NAME := my-module

SRCS := $(wildcard *.c)

all:
    $(CC) $(CFLAGS) $(LDFLAGS) -o $(OUTDIR)/$(NAME).so $(SRCS) -L$(LIBDIR) -lgowl
#+end_src

** Installing a Module
:PROPERTIES:
:CUSTOM_ID: installing-a-module
:END:
At startup the compositor looks for each module as =<name>.so= in two directories, in this order, and takes the first match:

1. =<exe-dir>/modules/= -- the directory next to the running binary, which is =build/release/modules/= in a development tree
2. =$(MODULEDIR)= -- =$(LIBDIR)/gowl/modules=, i.e. =$(PREFIX)/lib/gowl/modules/= or =lib64= depending on the platform; =/usr/local/lib/gowl/modules/= with the default prefix

=gowl --help= prints the resolved directories for the binary you have. There is no home-directory module search: a =.so= under =~/.local= or =~/.config= is never loaded. Per-user compositor code goes in =~/.config/gowl/config.c= instead (see the configuration guide).

=make install= installs every built module into =$(DESTDIR)$(MODULEDIR)=. To install one by hand, copy it into the directory =gowl --help= lists as =(installed)=:

#+begin_src sh
sudo cp my-module.so /usr/lib64/gowl/modules/     # or lib/, per your platform and prefix
#+end_src

Installing is not enough on its own. Only modules with =enabled: true= under =modules:= in the YAML config are loaded; =tile=, =monocle= and =float= are on unless explicitly disabled, everything else is off until named:

#+begin_src yaml
modules:
  my-module:
    enabled: true
#+end_src

A module that is enabled but whose =.so= is not found in either directory logs =Module 'my-module' is enabled but .so not found= and is skipped. Loading happens once, before the compositor is created; there is no runtime load, unload or reload for compositor modules, so a new or rebuilt =.so= means restarting the session.

** Module Configuration
:PROPERTIES:
:CUSTOM_ID: module-configuration
:END:
If your module needs configuration from the YAML config, it receives it through the =configure()= virtual method. The YAML =modules= section is parsed and the corresponding subsection is passed to each module by name:

#+begin_src yaml
modules:
  my-module:
    enabled: true
    example-value: 42
#+end_src

The =configure()= method receives a =gpointer= to the config data structure, which it can cast and process as needed.

*** The clipboard module

A history of everything that has been on the clipboard, text and
images. The compositor is the only thing that sees every selection
change, so this is where the history belongs --- a client that copies
and exits still leaves its text behind, and nothing has to be running in
the background to notice.

*Reading a selection is the part that needs care.* The data lives in the
owning client, and getting it means asking that client to write it down
a pipe. A synchronous read of that pipe on the compositor thread is fine
for a line of text and a frozen desktop for a megabyte of PNG: a client
that writes slowly holds the compositor for as long as it likes, and one
that never writes holds it forever. Every read here is driven by the
main loop, capped at 16 MiB, and abandoned after four seconds.

The store is =$XDG_STATE_HOME/gowl/clipboard=: an =index= of one
tab-separated row per entry (id, MIME type, size, single-line preview)
and one blob per entry, mode 0600. Two surfaces read it --- the bar's
=clipboard= widget and =M-x cmacs-clipboard= --- and they share the
store rather than a protocol, because both want the same list and either
may delete from it.

#+begin_src sh
gowl clipboard-list          # the index, newest first
gowl clipboard-copy 12       # put entry 12 back on the clipboard
gowl clipboard-delete 12
gowl clipboard-clear
gowl clipboard-path 12       # where the bytes are
#+end_src

Putting an entry back is itself a selection change, so the module
ignores its own writes; without that, pasting from the history would add
a duplicate every time. An exact repeat of the newest entry is skipped
too --- selections are re-announced for reasons that have nothing to do
with copying, and a history of one repeated line is not a history.

*** The osd module

The centred overlay for a level that just changed. A bar toast is the
wrong shape for that --- it is a message, it lives at the edge, and it
queues behind other messages. This is one transient pill in the middle
of the focused output, *replaced* rather than queued, with a filled
track because the number is not the point.

Reached by name through =ipc_command=, so a keybind, =gowl osd ...= and
cmacs all reach it identically and none of them needs to know the module
exists:

#+begin_src sh
gowl osd volume 45           # a level, 0..100
gowl osd volume 0 muted      # a level with a state word
gowl osd brightness 70
gowl osd show "Something"    # a message with no level
#+end_src

=cmacs-gowl-media= draws through it by default
(=cmacs-gowl-media-osd-function=) and falls back to the echo area when
the module is not loaded, so a session without it still reports the
level rather than going silent. The pill is click-through: it is
decoration, and a click belongs to whatever is beneath it.

*** The screenshot module

Captures through the scene, so a window is *the window* rather than the
rectangle it happens to occupy, and an area selection is an
in-compositor rubber band rather than a call out to =slurp=.

Both interactive modes --- =screenshot-area= and =screenshot-window=
with no client named --- dim the desktop as soon as they arm, drag or
highlight, and take =Escape= or a right-click as a cancel. The overlay
is destroyed before the capture, so none of it appears in the image.

They depend on =GowlMouseHandler= reaching modules at all, which the
compositor does from =gowl_compositor_motionnotify= and
=compositor_handle_button=. Those two calls did not exist for the
interface's whole life: =handle_motion= had no callers anywhere in the
tree and =dispatch_button= had none either, so an interactive module
could arm itself and then wait forever for input that could not
arrive. Results are
written as PNG (via cairo) under =save-directory= and, unless
=copy-to-clipboard= is turned off, offered on gowl's own selection as
=image/png=.

#+begin_src yaml
modules:
  screenshot:
    save-directory: ~/Pictures/Screenshots
    filename-format: "shot-%Y-%m-%d-%H%M%S.png"
    copy-to-clipboard: true
#+end_src

CMacs loads it by default. It is reached three ways: through
=GowlScreenshotProvider= (which the bar's =screenshot= widget uses; with
no module loaded that widget falls back to =grim= and =slurp=), through
=ipc_command= from a keybind, and through =gowl <command>= on the IPC
socket. The commands are =screenshot-area= (=screenshot-select=),
=screenshot-window=, =screenshot-screen= (=screenshot=),
=screenshot-all= and =screenshot-cancel=; the shipped config binds the
first three to =Super+Shift+S=, =Super+Print= and =Print=.

A bind reaching the module by name is what keeps the keybind, the CLI
and cmacs from having to know that this module exists --- and what makes
a missing module inert rather than broken.

A clipboard payload is written to the pasting client *by the main loop*,
not from the =wlr_data_source= send callback. That callback runs on the
compositor thread, and a screenshot is megabytes: a client that reads
slowly would otherwise hold the whole session for as long as it felt
like, and one that never reads would hold it forever.

*** Layout plugins and switching

All layout algorithms live in their respective =modules/= directories.
Standalone Gowl loads =tile=, =monocle= and =float= unless explicitly
configured with =enabled: false=. Enable =scrolling= in the =modules=
mapping to add a scrolling strip of columns (or rows on portrait monitors). CMacs loads all four by
default. Additional active layout providers join the same registry.

Layout selection and scroll offset are independent for each monitor's
tag view; combined tag masks have their own state. Focus changes reveal
offscreen windows, and the viewport clips content to its own monitor.
The layout-provider interface supports focus, scrolling and overflow
policy without putting layout algorithms in the compositor.

CMacs binds Super+< / Super+> to previous/next layout on the current tag,
which is also how the scrolling layout is reached: Super+s is the
scratchpad (see [[#scratchpad][Scratchpad]]). Super+Tab / Super+Shift+Tab
remain aliases, Super+t selects tile, and Super+[ / Super+] scroll the
strip.
Monitor-moving shortcuts use Super+Ctrl+Shift+comma/period. Super+Shift+j/k
swap the focused tiled client with the next/previous eligible client,
wrapping at either end and keeping focus on the moved window. The
=movestack= plugin supplies the same shortcuts to standalone Gowl;
config-level =move-stack= actions take precedence.

The =layout-indicator= plugin is loaded by default in CMacs and optional
in standalone Gowl. It displays the effective layout name for 1.2 seconds
at the active monitor's top center. Rapid changes replace one toast;
ordinary rearrangements do not retrigger it. It never takes focus or
intercepts clicks. Disable it in CMacs with
=(gowl-disable-module "layout-indicator")=.

The indicator also handles =toast-requested= on the compositor, with a
monitor and message string. It uses the same 1.2-second timer and replaces
any current notice. CMacs uses this to explain blocked close requests for
its hosting process. Disabling the indicator hides notices but does not
remove close protection.

*** Monitor orientation

Layouts adapt to each monitor's current logical dimensions on every
arrangement, including live mode and rotation changes. When height is
greater than width, tile puts the master above the stack (a horizontal
split), scrolling runs top to bottom, centered-master uses a central
horizontal band, and Fibonacci starts with a horizontal split. Square
and landscape monitors keep the normal orientation. Bars and gaps do
not affect this decision, and monitors choose independently. Monocle
still fills the usable area; floating windows retain their positions.
An explicitly enabled =vsplit= continues to select top/bottom tiling
on landscape and square monitors too.

*** Dropdown overlay

The default dropdown spans the output width and two-thirds of its usable
height. It is a fixed floating overlay, excluded from layout placement,
window swapping, dragging, resizing and fullscreen toggles. Super+grave
also accepts Super+Shift+grave/tilde. Toggling again or focusing another
app dismisses it while preserving the shell process. Opening and hiding
do not rearrange underlying tiles. Closing the shell allows a fresh
instance on the next toggle.

With =animation= enabled, the live shell slides from its configured edge
and reverses from its current position on rapid toggles. A second toggle
during startup keeps the shell hidden without a flash. Without animation,
visibility changes immediately.

*** Scratchpad
:PROPERTIES:
:CUSTOM_ID: scratchpad
:END:

The quake shell's twin from the other edge: a panel that slides up from
the bottom of the focused output holding any windows sent to it, tiled
in columns. It is the dropdown's size --- both panels come from
=gowl_overlay_panel_box()=, so the same settings give the same rectangle
--- and the same fixed floating overlay: showing it never rearranges the
tiles beneath it, it comes up over whichever tag is in view, and
focusing a window outside it rolls it away. While it is up its windows
have the keyboard and every keybind. Super+j / Super+k step across its
columns in the order they are drawn, wrapping at the ends, and Super+h /
Super+l move left and right (there is no master area to resize behind
the panel) --- instead of stepping down onto the tiles, which would roll
it away. Like every overlay, its windows get no shadow or frosted
backdrop from the blur module, so the columns meet edge to edge with
nothing drawn across the seam.

| Key                  | Command             | Effect                                    |
|----------------------+---------------------+-------------------------------------------|
| =Super+s=            | =scratchpad-toggle= | Slide the panel up, or roll it away       |
| =Super+Alt+s=        | =scratchpad-add=    | Send the focused window to it             |
| =Super+Ctrl+s=       | =scratchpad-remove= | Bring the focused window back to the tags |
| =Super+Ctrl+Shift+s= | =scratchpad-remove= | The same, with Shift                      |

The module has no keys of its own. Every operation is a command, so a
bind is ={ action: ipc_command, arg: "scratchpad-toggle" }= and the same
word works over the IPC socket and from an embedder through
=gowl_compositor_run_command()=, which is how cmacs reaches it. The
shipped =default-config.yaml= binds the keys above and enables the
module. Super+Ctrl+s has to be bound: left to fall through, a terminal in
the panel gets it as Ctrl+S --- XOFF --- and stops echoing, which looks
exactly like the window died.

| Command                  | Reply                  | Does                                                  |
|--------------------------+------------------------+-------------------------------------------------------|
| =scratchpad-toggle=      | =OK shown N=, =OK hidden= | Show if hidden, hide if shown                      |
| =scratchpad-show=        | =OK shown N=           | Show; when already up, re-tile and refocus            |
| =scratchpad-hide=        | =OK hidden=            | Hide                                                  |
| =scratchpad-add [ID]=    | =OK added N=           | The focused window, or client ID, joins               |
| =scratchpad-remove [ID]= | =OK removed N=         | It leaves onto the selected output's tags, focused    |
| =scratchpad-status=      | =OK visible=0 count=2 ...= | Visibility, member ids and settings, as key=value |

N is how many windows the scratchpad holds afterwards. The status line
is =OK visible=V count=N members=ID,ID width-pct=W height-pct=H width=PX
height=PX gap=PX=; fractions always print with a '.', whatever the
locale. Anything that fails is an =ERROR ...= reply saying why: the
scratchpad is empty, the window is already a member, it cannot join (an
embedded client, somebody else's overlay such as the dropdown's shell, a
popup), or an id names no window.

*Joining.* The window leaves the layout as a hidden overlay on no tag
--- so no tag counts it as occupied --- and its monitor re-tiles without
it. It is the window focused the next time the panel comes up. Members
are columns in the order they joined, split evenly with any leftover
pixels going one each to the first columns, and every column shares the
panel's top edge and height, which is why several windows slide up as
one panel.

*Leaving.* =scratchpad-remove= rolls the rest away, puts the window back
on the tags in view --- tiled if it was tiled, floating where it floated,
measured from the window area so it lands in the same place on another
output --- and focuses it. A window that closes simply leaves, and the
rest close the gap. One that unmaps without closing, such as an app
hiding in its tray, leaves too, and comes back as an ordinary window if
it maps again. Disabling the module gives every window back, so none is
ever stranded as a hidden overlay with nothing left to show it.

*Settings* (=modules: scratchpad:= in YAML, =gowl-configure-module= under
cmacs) are the dropdown's own:

| Key          | Default    | Meaning                                                  |
|--------------+------------+----------------------------------------------------------|
| =width-pct=  | =1.0=      | Fraction of the usable width, above 0 and at most 1      |
| =height-pct= | =0.666667= | Fraction of the usable height                            |
| =width=      | =0=        | Pixels, 0 to 65535; when not 0 it wins over =width-pct=  |
| =height=     | =0=        | Pixels, 0 to 65535; when not 0 it wins over =height-pct= |
| =gap=        | =0=        | Pixels between the columns, 0 to 512                     |

A bad value is refused with a warning naming the key, and the old value
kept. A shown panel takes a new size at once.

*How it is built.* The module decides only which windows, where and
when. The compositor does the window management, through three calls
any module can use: =gowl_compositor_adopt_overlay()= takes a window out
of tiling as a hidden overlay in a non-zero /overlay group/, recording
whether it floated and where; =gowl_compositor_present_overlay()= --- the
dropdown's call --- shows and hides it; =gowl_compositor_release_overlay()=
gives it back. The group keeps Super+j / Super+k inside a shown panel
(=gowl_focus_stack_accepts()=). The compositor itself hands an adopted
overlay back when its window unmaps, which is why a remapped window
cannot come back invisible; =tests/test-overlay-guard.sh= keeps that call
and the focus-stack one in place. Hidden overlays are on no tag, so the
session file leaves them out and jumping to one
(=gowl_compositor_show_client()=) never switches an output to viewing no
tags.

*** Alpha Module

:END:
The alpha module controls per-client window opacity. When the focused client changes, the previously focused client fades to =unfocused-alpha= and the newly focused client is set to =focused-alpha=.

*Interfaces:* =GowlStartupHandler=, =GowlShutdownHandler=

*Configuration keys:*

| Key               | Type  | Default | Description                               |
|-------------------+-------+---------+-------------------------------------------|
| =focused-alpha=   | float | 1.0     | Opacity for the focused window (0.0--1.0) |
| =unfocused-alpha= | float | 0.8     | Opacity for unfocused windows (0.0--1.0)  |
| =dim-inactive=    | bool  | false   | Darken unfocused windows with a translucent black layer, keeping them opaque; what reads as "not this one" on a busy tag |
| =dim-strength=    | float | 0.25    | How dark, 0.0 (nothing) to 1.0 (black)    |

*YAML example:*

#+begin_src yaml
modules:
  alpha:
    enabled: true
    focused-alpha: 1.0
    unfocused-alpha: 0.7
#+end_src

*Implementation notes:*

- Uses =gowl_client_set_alpha()= which walks the client's scene tree via =wlr_scene_node_for_each_buffer()= and calls =wlr_scene_buffer_set_opacity()= on each buffer.
- Connects to the compositor's =focus-changed= signal to automatically apply alpha on focus changes.
- On deactivation, resets all clients to fully opaque (alpha 1.0) --- while the compositor is alive. The compositor pointer is a weak pointer, so a deactivate that runs after the compositor is finalized (the module manager is released last) finds =NULL= and does nothing; see [[#outliving-the-compositor][A module outlives the compositor]].
- Applying configuration while running immediately re-applies alpha to all existing clients.

** Tips
:PROPERTIES:
:CUSTOM_ID: tips
:END:
- Set your module's =priority= property to control dispatch order relative to other modules. Lower values are dispatched first.
- Always check =gowl_module_get_is_active()= before performing module operations in signal handlers.
- Use =g_autoptr()= and =g_steal_pointer()= for memory management.
- Return =TRUE= from =handle_key= / =handle_button= only if you actually consumed the event; returning =TRUE= prevents other handlers from seeing it.
- The module =.so= stays loaded for the lifetime of the compositor. Do not call =g_module_close()= on yourself.

** A module outlives the compositor
:PROPERTIES:
:CUSTOM_ID: outliving-the-compositor
:END:
The compositor only borrows its module manager --- =gowl_compositor_set_module_manager()= takes no reference --- so whoever owns both releases the manager after the compositor. =main()= tears down in this order: =gowl_module_manager_dispatch_shutdown()= while the compositor is alive, then the compositor, then the manager, whose dispose calls =deactivate= on every module that is still active. So =deactivate= and =finalize= run with the compositor already finalized, and a module that touches it there is touching freed memory.

A module that keeps the compositor pointer it was given in =on_startup= therefore has to be able to tell that it is gone:

- Hold it with =g_object_add_weak_pointer()=. GObject sets the pointer to =NULL= when the compositor goes and destroys every handler connected to the compositor along with it, so a =deactivate= that finds =NULL= has nothing left to disconnect. Take the weak pointer back yourself when you detach, and when the module is finalized first, or GObject writes into freed memory later. One =detach= function that does both, called from =deactivate=, =finalize= and a repeated =on_startup=, is the shape =windowrules=, =alpha=, =osd=, =clipboard= and =layout-indicator= share; =dropdown= and =scratchpad= do the same inline.
- Or connect with =g_signal_connect_object()= and never disconnect by hand: GObject drops the handler with whichever of the two dies first. =roundcorners=, =wallpaper= and =screenlock= connect =renderer-replaced= this way.

A =GowlShutdownHandler= is the right place to let go while the compositor is alive, but it is not enough on its own: nothing obliges an embedder to dispatch shutdown, and cmacs's =gowl-stop= finalizes the compositor without it. =alpha= disconnected in its shutdown handler and still disconnected from freed memory in =deactivate= whenever shutdown had not run first.

=windowrules= kept a borrowed pointer and disconnected its =client-pre-map= handler in =deactivate=, which ended every teardown with two GLib criticals:

#+begin_example
GLib-GObject-CRITICAL **: instance with invalid (NULL) class pointer
GLib-GObject-CRITICAL **: g_signal_handler_disconnect: assertion 'G_TYPE_CHECK_INSTANCE (instance)' failed
#+end_example

The first line describes whatever the freed memory holds by then, so it also appears as =instance of invalid non-instantiatable type 'guchar'=. =tests/test-compositor-teardown.c= loads everything cmacs =--gowl= loads but the bar, starts a headless compositor under it, and tears it down with and without a shutdown dispatch; a critical anywhere fails it. No client is mapped there, so what a module keeps per client is outside its reach.

** Scene-effect dispatch order

Every provider is offered each event in priority order and the first to
*claim* a consumable one owns it. Two things follow, and both were
learned by breaking them:

- *Being first means nothing about whether a module should act.* A
  module that checks whether it is =gowl_module_manager_get_scene_effect=
  and stands down otherwise will switch itself off the moment anything
  else sorts ahead of it. The animation module did exactly that, so
  adding unrelated modules to the default set silently ended every
  window animation --- no error, no warning, nothing in the config to
  explain it. =tests/test-effect-order-guard.sh= now refuses that
  pattern.
- *Equal priorities resolve to registration order.* Every shipped effect
  module carries the same default priority and =g_ptr_array_sort= is not
  stable, so index 0 was previously unspecified and moved whenever the
  loaded set changed. Ties now break on the order modules were
  registered, which is what callers assumed all along.

** Animation and native scene effects

The =animation= module implements =GowlSceneEffect= and is opt-in in
standalone Gowl (=modules.animation.enabled: true=). CMacs loads it by
default before any clients map. Timing, curves, pop scale and jiggle
strength retain their existing top-level configuration keys; see
[[file:configuration.org::#animations][animation configuration]].

=GowlSceneEffect= is a native compositor-thread interface. A single
provider owns scene presentation, selected by module priority. Its
=client_event= hook receives final bounded geometry before the client
configure, visibility reveals, pointer releases, and unmap/destroy
notifications before surface resources are released. A geometry event
returns true only when the provider has placed the scene and borders;
otherwise the core applies the final rectangle immediately.

=get_geometry= and =alpha_changed= keep independent decorators and
client opacity synchronized. =surface_at= translates input through
replacement visuals. =frame= runs before the output commit and reports
whether that output needs another frame --- which matters, because an
output nothing asks to redraw is not drawn at all; it runs on every frame
event, drawn or not. =frame_done= lets providers
maintain callbacks for temporarily hidden live content. =monitor_removed=
releases resources tied to an output, and =finish= runs before compositor
scene/renderer teardown. After that =finish= no hook reaches a provider
again, so a provider must let go of everything there rather than wait to
hear about the clients teardown destroys. =finish= also runs when a GPU
reset replaces the renderer, and then hooks carry on: a provider must
rebuild what it let go of on demand, from the compositor's current
renderer, never from a pointer kept from before. Deactivation must also
restore ordinary live
presentation and release all held buffers. Providers own their state;
there are no animation clocks or snapshots in the core client structure.

** After a GPU reset

When wlroots reports the renderer lost, the compositor swaps in a new one
(see [[file:architecture.org][architecture]]), and every texture the old
renderer made goes with it. For a scene buffer that texture is usually
the only copy of its pixels: the scene uploads a =wlr_buffer= and then
releases it, so a module that hands the scene a buffer and drops its own
reference --- the normal pattern --- has nothing left to draw from. Such
a node shows nothing until it is given a buffer again.

So once the new renderer is in place the compositor emits
=GowlCompositor::renderer-replaced=, and a module that draws into scene
buffers of its own connects to it at startup and redraws them:

#+begin_src c
static void
my_on_renderer_replaced(GowlCompositor *compositor, gpointer user_data)
{
	MyModule *self = MY_MODULE(user_data);

	/* Every buffer handed to the scene before now is gone: draw each
	 * again, even where nothing about it has changed. */
	my_redraw_all(self);
}

/* In the startup handler: */
g_signal_connect_object(compositor, "renderer-replaced",
                        G_CALLBACK(my_on_renderer_replaced), self, 0);
#+end_src

A cache that skips redrawing unchanged content has to be bypassed there,
or the redraw is skipped as a no-op; the bar forgets its render
signatures first for exactly that reason. The wallpaper, bar,
roundcorners and screenlock modules do this. Surfaces that hide by
themselves (the OSD, the layout indicator) do not: at worst one vanishes
a moment early. Scene effects also get =finish= before the swap, as
above, for their GL objects. Client windows need nothing: each comes
back on its next commit. =tests/test-gpu-reset.c= loads the modules and
checks that nothing they drew is left blank.

** Frames on an idle output

The compositor draws an output only when something on it changed:
damage, a frame callback, a screencopy, an effect whose =frame= hook
reported it is still moving, a gamma ramp. A frame event with none of
those commits nothing and does not emit =GowlCompositor::frame-rendered=,
and an output nobody asks to redraw sends no frame events at all. So a
module that needs a steady stream of frames from an unchanging screen
asks for each next one itself, from its =frame-rendered= handler:

#+begin_src c
wlr_output_schedule_frame(gowl_monitor_get_wlr_output(GOWL_MONITOR(monitor)));
#+end_src

The recording module does exactly this while it records, and schedules a
first frame on every output when it starts: ffmpeg reads a fixed frame
rate, so without it a stretch of screen standing still would drop out of
the video's timeline. =tests/test-idle-output.c= checks the contract.

** Six effect modules, one interface

=animation=, =cube=, =expo=, =switcher=, =magnifier= and =blur= all
implement =GowlSceneEffect=, all opt in through the =modules= mapping,
and all are loaded by CMacs by default. They are separate plugins rather
than one because each is a separate decision: somebody who wants shadows
and no cube, or a magnifier and nothing else, configures exactly that.

*How six providers share one interface.* Every hook is either
CONSUMABLE or BROADCAST, and which one it is is a property of the hook
rather than of the module:

- =client_event=, =get_geometry= and =surface_at= decide where a window
  IS and what the pointer hits. Two modules cannot both answer, so the
  first provider in priority order that claims one owns it. This is the
  rule that stops two modules fighting over one scene node.
- =alpha_changed=, =frame=, =frame_done=, =monitor_removed=, =finish=
  and =client_placed= are "here is a tick", "put your things away" and
  "the window is drawn here now". Every provider gets them, because a
  module that misses its own teardown leaks buffers into a renderer that
  is going away, and one that decorates a window has to follow it
  whichever module moved it. A decoration therefore follows
  =client_placed=, never =GEOMETRY=: the animation module claims every
  tile's placement, which is how the blur module's shadow and backdrop
  used to keep a resized window's old size.

Dispatch lives in =src/core/gowl-effects.c= and is pinned by
=tests/test-effects.c=. Both failure modes are silent: a consumable hook
that did not stop at the first claimant would let two modules place the
same window, and a broadcast hook that stopped early would switch off
every module after it in priority order.

The consequence for a module author is that there is nothing to forward.
Implement what you need, return =FALSE= or =NULL= for the rest, and pick
a priority. The current order is =cube= (-10), =expo= (-8), =switcher=
(-6), =animation= (0), =blur= (10), =magnifier= (100); the effects that
own a whole output sort before the ones that decorate a window, and the
magnifier sorts last because it magnifies whatever the others drew.

** The shared effect layer

The five newer effects contain no GL. Every context bracket, shader,
texture, capture and scene-sheet lives in =src/fx= (see *Visual effect
layer* in [[file:architecture.org][architecture]]), because that is where a mistake is
expensive and invisible --- a context left current, a scene node left
hidden, a buffer freed after its renderer. One implementation, one set of
tests (=tests/test-fx-render.c=, against a real GPU), five callers.

What is left in each module is the part that is actually about that
effect: the shape of a prism and where the camera stands (=cube=), how a
grid of tiles becomes one screen again (=expo=), where the cards go
(=switcher=). Those parts are pure arithmetic in their own translation
units, so =tests/test-cube.c= and =tests/test-expo.c= check them without
a display.

*None of them adds a renderer.* They borrow the EGL context wlroots'
GLES2 renderer already owns. Under any other renderer =gowl_fx_gl_new()=
returns %NULL, every module treats that as "sit this session out", and
the desktop behaves exactly as it did without them.

** Taking an output, and giving it back

An effect that replaces the whole screen --- the cube's rotation, the
overview, the switcher --- parks one opaque monitor-sized buffer in the
scene for its duration. It hides what is below it by COVERING it, never
by switching a scene layer off: the layers are shared by every output
while tags are per-monitor, so an effect that disabled one to make room
on one screen would blank the other. Only the few things gowl stacks
ABOVE that point (fullscreen clients, embedder-pinned overlays) are taken
down individually, and they are put back from a held reference so a
window closed mid-effect cannot leave a dangling one.

=tests/test-cube-guard.sh= fails the build if the cube stops claiming
only its own reveal, or starts taking a shared layer. Both fail silently
otherwise: the symptom is an absence, not a crash.

** The desktop cube

The =cube= module turns the desktop as one side of a solid when the tag
changes, one face-step per tag crossed. Opt-in in standalone Gowl
(=modules.cube.enabled: true=); CMacs loads it by default. See
[[file:configuration.org::#cube][cube configuration]] for the settings and for what each side contains.

The one call it claims is a visibility reveal on a monitor whose tags
have just changed: the rotation's first captured side already shows those
windows, so letting them ALSO fade in would fade the desktop up after the
rotation had landed. Everything else --- window geometry, opacity,
hit-testing --- reaches the animation module untouched.

Module shared objects remain resident after registering static GTypes,
so restarting a compositor manager cannot leave GLib holding unloaded
class vtables. Module instances and their resources are still disposed.
