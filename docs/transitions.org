#+title: Tag transitions
#+description: What a tag switch looks like: the transition modules, how one is chosen, and how to write another

* Overview

A tag switch can cut, or it can move: the desktop turns as a cube, slides sideways, curls away like a page, melts, burns or shatters into the next one. Each of those is its own *module* under =modules/=, and any number of them can be loaded at once -- cmacs loads them all. One setting, =tag-transition=, picks which one runs; =random= picks a different one at every switch; =none= switches instantly.

=Super+:= (=Super+Shift+semicolon=, the =cycle_tag_transition= action) steps through the loaded transitions at runtime, with =random= as the last stop before the tour starts again, and a toast names the one you are on. The cube is the default.

| Selection | What a switch does |
|-----------+--------------------|
| a module's name (=cube=, =slide=, ...) | that transition, when its module is loaded; an instant switch otherwise |
| =random= | a loaded transition chosen at each switch, never the same one twice running |
| =none= | an instant switch |

Every transition needs the GLES2 renderer (the effect layer borrows its context) and sits out under any other renderer, on a rotated output, while the session is locked, and on outputs other than the focused one unless =tag-transition-all-monitors= is set.

* Choosing one
:PROPERTIES:
:CUSTOM_ID: choosing
:END:

#+begin_src yaml
tag-transition: pagecurl          # or random, or none
tag-transition-duration: 460      # ms, scaled per transition
tag-transition-curve: "ease-in-out-cubic"
tag-transition-all-monitors: false
modules:
  slide:    { enabled: true }     # standalone gowl: load the ones you want
  pagecurl: { enabled: true }
#+end_src

At runtime:

#+begin_src sh
gowl-msg tag-transition                 # OK cube
gowl-msg tag-transition list            # ["cube","slide","pagecurl","random"]
gowl-msg tag-transition next            # what Super+: does
gowl-msg tag-transition random
gowl-msg -c transition.set name=melt duration=900
gowl-msg -s -j transition.changed
#+end_src

Under cmacs, =cmacs-gowl-tag-transition= is the setting (pushed at every =cmacs-gowl-mode=, quietly when it is already in force) and =M-x cmacs-gowl-cycle-tag-transition= / =M-x cmacs-gowl-set-tag-transition= the commands; from Lisp, =gowl-set-tag-transition=, =gowl-tag-transition= and =gowl-tag-transitions=.

A key per transition is a keybind with an argument:

#+begin_src yaml
keybinds:
  "Super+Shift+semicolon": { action: cycle_tag_transition }
  "Super+Ctrl+semicolon":  { action: cycle_tag_transition, arg: prev }
  "Super+Alt+semicolon":   { action: cycle_tag_transition, arg: random }
#+end_src

* The transitions
:PROPERTIES:
:CUSTOM_ID: the-transitions
:END:

In the order Super+: visits them (a module not loaded is skipped):

| Name    | Module          | What it looks like |
|---------+-----------------+--------------------|
| =cube=  | =modules/cube=  | The desktop turns as one side of a solid, one turn per tag crossed. Its own settings (=cube-*=) and a three-finger swipe; see [[file:configuration.org::#cube][the cube]] |
| =slide= | =modules/slide= | Pushed off sideways with the next one following, left for a higher tag and right for a lower; mid-flight both lift a little off the screen with a gap between them and the one leaving dims |
| =fade=  | =modules/fade=  | A plain crossfade; nothing moves.  The quickest of them (0.8x the duration), for anyone who would rather the desktop stayed still |
| =iris=  | =modules/iris=  | The next desktop opens out of a soft-edged circle at the pointer (the output's centre when the pointer is elsewhere), the old one shadowed round the hole; back to a lower tag it closes into the pointer instead |
| =flip=  | =modules/flip=  | The desktop is a card with the next tag on its back: half a turn about its vertical axis in perspective, the camera easing back so the near edge is never clipped, each side darkening as it turns from the light |
| =pagecurl= | =modules/pagecurl= | Turned like a page taken by its bottom corner -- from the right for a higher tag, the left for a lower -- its back showing pale as it comes over, the next desktop underneath in its shadow. 1.45x the duration |
| =carousel= | =modules/carousel= | The desktops stand round a large ring facing out, a gap between each; the ring swings round to the next tag and shows every tag it passes, the camera easing back so the neighbours come into view. Grows with the distance (=step_scale=) |
| =sphere= | =modules/sphere= | The desktop bends onto the front of a lit globe, the globe turns half a revolution, and the next desktop -- mapped onto its far side -- unwraps flat. Three acts, so 2x the duration |
| =burn=  | =modules/burn=  | The desktop catches near the pointer and burns away along a ragged, flickering edge -- scorched ahead of the flames, charred behind -- the next desktop showing through the ash; a different fire every switch. Goes with the =embers= backdrop |
| =ripple= | =modules/ripple= | A drop falls at the pointer: the next desktop spreads out behind the wavefront, both desktops refracted through decaying rings whose crests catch the light, the swell calming as it lands. Goes with the =water= backdrop |
| =pixelate= | =modules/pixelate= | The desktop coarsens into a mosaic, changes while the blocks are biggest (56 px on a 1080-row output, scaled with the output), and sharpens into the next one |
| =glitch= | =modules/glitch= | A bad signal: torn slices re-dealt 24 times a second, each flipping to the next desktop at its own moment, split colour, scanlines, grain and the odd block from the wrong place. Quick on purpose (0.75x) |
| =melt=  | =modules/melt=  | The screen wipe from a certain 1993 shooter: the desktop runs down in 160 dripping columns, each starting at its own moment and falling faster as it goes, the next desktop behind it |
| =shatter= | =modules/shatter= | The desktop is struck like glass at the pointer: cracks open, pieces break loose in a wave spreading from the impact, and each tumbles away under gravity onto the next desktop |
| =explode= | =modules/explode= | The desktop blows apart from the pointer: every piece flies outward and towards you at once, slowing, spinning and fading, while the next desktop swells into place behind as though the blast had pushed it there |
| =implode= | =modules/implode= | The opposite of explode: the desktop breaks up and is pulled into the pointer, nearest pieces first, each accelerating, spinning and shrinking to nothing as it reaches the point, the next desktop settling behind |
| =zoom=  | =modules/zoom=  | The tags as a stack of desktops: to a higher tag the one you are on sinks away and fades while the next settles from just in front of the glass; back, the one you are on rushes past and the one behind comes forward |

* How it works
:PROPERTIES:
:CUSTOM_ID: how-it-works
:END:

** One arbiter, many modules

Every transition watches every tag switch on its own, and only one may animate it -- two sheets over one output would fight. The arbiter is =src/core/gowl-tag-transition.c=:

- A module *registers* its name and a label for the toast (=gowl_compositor_register_tag_transition()=), from its startup hook and again lazily from any scene-effect hook, and withdraws it when it is deactivated.
- =tag-transition= *selects* one.
- For each switch, every module asks =gowl_compositor_tag_transition_is(compositor, output, "slide")=; only the one named runs. The answer comes from =gowl_compositor_tag_transition_pick()=, which is decided *once per output per tag set*: for =random= that is what makes every module hear the same name about the same switch, and the next switch a new draw.

The registry lives in the compositor rather than in a "host" module because modules are separate shared objects and cannot call each other.

The tour order is written out in =canonical_order[]= rather than taken from registration order, which is whatever order the modules loaded in and would make Super+: a different tour on every machine. A third-party transition not in the list follows it, in registration order.

** The shared host

=src/fx/gowl-fx-transition.c= is everything a transition needs except its picture, factored out of the cube:

- switches are noticed by *polling* the output's tags in the frame hook, against a memory kept on the output, rather than by a signal that fires before the scene is rearranged;
- both desktops (and, for a =multi_step= kind, every desktop crossed, at half size) are *captured up front* in one frame, with the bar, notifications and the recording indicator left out -- they stay live on top;
- the output is taken with one opaque *sheet*, never by switching off a shared scene layer;
- the *reveal* fade the switch starts is claimed and dropped, because the first captured frame already shows those windows -- and nothing else is ever claimed (=tests/test-transition-guard.sh=);
- a switch *mid-flight* ends the run and starts a fresh one from where it was headed;
- the run ends on its clock, on an output being unplugged, or on a frame that cannot be drawn.

** Drawing

Modules contain no GL (=tests/test-transition-guard.sh=). They draw through three primitives in =src/fx=:

| Primitive | For |
|-----------+-----|
| =gowl_fx_transition_pass_desktop()= | a whole desktop as a flat quad, through any MVP -- slide, zoom, flip, carousel |
| =gowl_fx_pass_blend()= | a full-screen fragment shader reading both desktops -- fade, iris, burn, ripple, pixelate, glitch, melt, page curl |
| =gowl_fx_pass_mesh()= | textured triangles built on the CPU each frame -- the sphere, shatter, explode, implode; the last three through =gowl_fx_shards_new()= and =gowl_fx_transition_draw_shards()=, which break the desktop into crack-free triangles and draw them over the new one |

The one rule every transition keeps is the *seam*: at progress 0 the picture is exactly the desktop being left, and at 1 exactly the one arrived at. Those frames are presented, and anything "nearly" the desktop there flashes on every switch. =gowl_fx_pass_blend()= enforces it for the shaders; =tests/test-transition-render.c= checks every transition against it on a real GPU.

* Writing a transition
:PROPERTIES:
:CUSTOM_ID: writing
:END:

A transition module is a kind and a draw function:

#+begin_src c
#include "fx/gowl-fx-transition-module.h"

static gboolean
fade_draw(GowlFxPass *pass, GowlFxTransitionRun *run, gdouble eased,
          gdouble linear)
{
	GowlFxBlendParams p;

	gowl_fx_blend_params_init(&p);
	p.kind = GOWL_FX_BLEND_FADE;
	p.from = run->from.tex;
	p.to = run->to.tex;
	p.progress = (gfloat)eased;
	return gowl_fx_pass_blend(pass, &p);
}

static const GowlFxTransitionKind fade_kind = {
	.name = "fade", .label = "Fade",
	.duration_scale = 1.0,
	.draw = fade_draw,
};

GOWL_FX_DEFINE_TRANSITION_MODULE(GowlModuleFade, gowl_module_fade,
                                 &fade_kind, "0.1.0",
                                 "Crossfades between tags")
#+end_src

=run= carries both desktops, the direction (=dir=, +1 towards a higher tag), the steps crossed, the pointer's position on the output (=center=, for effects that start where you are looking) and a random =seed= for the switch. =setup= / =teardown= hold per-run state such as shards. Add the name to =canonical_order[]= in =src/core/gowl-tag-transition.c= (the guard fails otherwise) and a row to the table above.
